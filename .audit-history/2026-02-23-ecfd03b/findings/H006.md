# Finding: H006 - 23-Hour Dead Zone Fund Lockup Griefing

## Executive Summary

The SolShot escrow program contains a confirmed 23-hour dead zone created by the gap between the 1-hour settlement deadline (`SETTLEMENT_TIMEOUT_SECONDS = 3600`) and the 24-hour player cancellation timeout (`TIMEOUT_SECONDS = 86400`). Once both players deposit and the match becomes Active, the authority has exactly 1 hour to call `settle_match`. After that window expires, the authority can no longer settle (blocked by line 242), but players cannot call `cancel_match` on an Active match until 24 hours have elapsed from `activated_at` (enforced by lines 340-344). No other instruction can act on the Active match during this 23-hour window.

This is a **design-level vulnerability**: a malicious or unresponsive authority can intentionally allow the settlement window to expire, locking up to 200 SOL (2 × MAX_WAGER = 100 SOL each) per match for up to 23 hours with zero on-chain recourse. Because `cancel_match` is blocked during a program pause (line 644) while `permissionless_reclaim` requires 48 hours (line 409), a malicious authority who also pauses the program can extend the lockup to 48 hours. The finding is CONFIRMED because the dead zone is mechanically precise, fully traceable in code, requires no special setup beyond having an Active match, and no escape path exists between the 1-hour and 24-hour marks.

## Hypothesis Investigated

After the 1-hour settlement deadline expires, the authority can no longer settle, but players cannot cancel until 24 hours. This creates a 23-hour window where funds are locked. A malicious authority could intentionally not settle to grief players.

Attack vector:
1. Both players deposit; match becomes Active
2. Authority intentionally does NOT settle within the 1-hour window
3. Settlement deadline expires — authority can no longer settle
4. Players cannot cancel until 24h from `activated_at`
5. Funds locked for 23 hours with no recourse

## Investigation Path

### Step 1: Verify the Exact Gap Between SETTLEMENT_TIMEOUT_SECONDS and TIMEOUT_SECONDS
**Location:** `programs/solshot-escrow/src/lib.rs:20,26`
**Finding:** The constants are unambiguous. `SETTLEMENT_TIMEOUT_SECONDS = 3600` (1 hour). `TIMEOUT_SECONDS = 86400` (24 hours). The gap is exactly 86400 - 3600 = 82800 seconds = 23 hours.
**Evidence:**
```rust
/// 24-hour timeout for auto-refund after match activation (in seconds)
const TIMEOUT_SECONDS: i64 = 86400;

/// 1-hour settlement deadline after match activation (OC-07)
const SETTLEMENT_TIMEOUT_SECONDS: i64 = 3600;
```

### Step 2: Verify the Settlement Deadline Enforcement
**Location:** `programs/solshot-escrow/src/lib.rs:236-244`
**Finding:** After `activated_at + 3600`, `settle_match` unconditionally returns `EscrowError::SettlementExpired`. The `activated_at > 0` guard is redundant-but-safe (any Active match guaranteed to have `activated_at > 0` from line 209); it does not create a bypass.
**Evidence:**
```rust
if ctx.accounts.escrow.activated_at > 0 {
    let deadline = ctx.accounts.escrow.activated_at
        .checked_add(SETTLEMENT_TIMEOUT_SECONDS)
        .ok_or(EscrowError::ArithmeticOverflow)?;
    require!(
        Clock::get()?.unix_timestamp <= deadline,
        EscrowError::SettlementExpired
    );
}
```

### Step 3: Verify the Cancel Authorization Logic for Active Matches
**Location:** `programs/solshot-escrow/src/lib.rs:336-344`
**Finding:** The authorization check is a precise compound boolean. For an Active match (`escrow_state == MatchState::Active`), the `is_authority` branch requires `AwaitingDeposits` — which is false — so it is blocked. The `is_player` branch requires either `escrow_state == MatchState::AwaitingDeposits` (false) OR `is_timed_out` (false until `now > activated_at + 86400`). Both branches fail between hours 1 and 24. The `require!` macro returns `EscrowError::Unauthorized`.
**Evidence:**
```rust
let is_authority = caller == config_authority;
let is_player = caller == ctx.accounts.escrow.player_one
    || caller == ctx.accounts.escrow.player_two;

require!(
    (is_authority && escrow_state == MatchState::AwaitingDeposits)
    || (is_player && (escrow_state == MatchState::AwaitingDeposits || is_timed_out)),
    EscrowError::Unauthorized
);
```

For an Active match between hours 1-24:
- `is_authority && AwaitingDeposits` → `true && false` → false
- `is_player && (AwaitingDeposits || is_timed_out)` → `true && (false || false)` → false
- Combined: false → `EscrowError::Unauthorized`

### Step 4: Verify No Other Instruction Can Act on an Active Match During Hours 1-24
**Location:** `programs/solshot-escrow/src/lib.rs` — all 9 instructions
**Finding:** Exhaustive scan of all instructions:
- `initialize_config`: creates config, no match interaction
- `update_config`: modifies config only
- `pause_program` / `unpause_program`: toggles pause flag only
- `create_match`: creates a NEW escrow (`init` constraint), cannot interact with existing
- `deposit_wager`: requires state == `AwaitingDeposits` (line 163-166), fails on Active
- `settle_match`: blocked after hour 1 by deadline check (lines 240-243)
- `cancel_match`: blocked for players between hours 1-24 (lines 340-344)
- `permissionless_reclaim`: requires `now > timeout_reference + 172800` (48 hours), blocked until hour 48

**No instruction can act on an Active match between hours 1 and 24.** This is a complete coverage verification.

### Step 5: Verify the Pause Interaction That Extends Lockup to 48h
**Location:** `programs/solshot-escrow/src/lib.rs:640-649, 381-438`
**Finding:** `cancel_match`'s `CancelMatch` account struct includes a pause guard constraint (line 644). `permissionless_reclaim`'s `PermissionlessReclaim` struct intentionally excludes the config account entirely (lines 653-681), making it immune to pause. If the authority pauses the program during the 23-hour dead zone, `cancel_match` remains blocked even after the 24-hour mark. The only escape becomes `permissionless_reclaim` at 48 hours. The authority would need to call `pause_program`, which requires the authority signer.
**Evidence:**
```rust
// CancelMatch — has pause guard (line 644):
constraint = !config.is_paused @ EscrowError::ProgramPaused,

// PermissionlessReclaim — NO config account, NO pause guard:
pub struct PermissionlessReclaim<'info> {
    pub escrow: Account<'info, MatchEscrow>,
    pub caller: Signer<'info>,
    pub player_one: UncheckedAccount<'info>,
    pub player_two: UncheckedAccount<'info>,
    pub system_program: Program<'info, System>,
    // NOTE: no config account — intentional DCA-02 escape hatch
}
```

### Step 6: Verify Maximum Capital at Risk
**Location:** `programs/solshot-escrow/src/lib.rs:32`
**Finding:** `MAX_WAGER_LAMPORTS = 100_000_000_000` (100 SOL). A match escrow holds 2 × wager = up to 200 SOL. Multiple simultaneous matches multiply this figure linearly. There is no on-chain limit on the number of concurrent Active matches.

## Invariant Analysis

### Target Invariant
Player funds deposited into an Active escrow should always be accessible via some resolution path. Specifically: funds should never be unresolvable for an extended period due to authority inaction.

### Enforcement Points
| Location | What It Enforces | Complete? |
|----------|-----------------|-----------|
| `lib.rs:240-243` | Settlement only within 1 hour of activation | Yes — enforced strictly |
| `lib.rs:340-344` | Players can only cancel Active matches after 24h timeout | Yes — enforced strictly |
| `lib.rs:408-411` | Permissionless reclaim only after 48h | Yes — enforced strictly |
| `lib.rs:644` | `cancel_match` blocked when paused | Yes — enforced strictly |
| `lib.rs:653-681` | `permissionless_reclaim` has no pause guard | Yes — intentional |

### Enforcement Gap Assessment
The invariant "funds are always resolvable within a reasonable time" is NOT enforced between hours 1 and 24. The three enforcement points above create a precise 23-hour gap. Settlement expires at hour 1; player cancel requires hour 24. The code fully and consistently enforces these boundaries — but the gap between them is the vulnerability. The 48-hour permissionless reclaim exists but only further extends the timeline.

During a pause: the gap extends further. `cancel_match` (24h) is blocked while paused; only `permissionless_reclaim` (48h) remains available. A malicious authority can extend the effective lockup from 23 hours to up to 47 hours (pause immediately after settlement deadline, force all resolution through the 48h path).

## Blocking Factors
- **24h player cancel (partial):** `lib.rs:329-333` — players CAN recover funds, but only after 24 hours, not during the 23-hour dead zone
- **48h permissionless reclaim:** `lib.rs:408-411` — absolute escape hatch, but only after 48 hours
- **`permissionless_reclaim` bypasses pause:** `lib.rs:653-681` — ensures no permanent fund lockup, but 48h is a long time

## Enabling Factors
- **No authority-cancel path for Active matches:** `lib.rs:341` — authority is explicitly prohibited from cancelling Active matches, closing the natural escape valve
- **No "expired settlement" state:** There is no intermediate state between Active-and-unsettled and timed-out. The program treats a match whose settlement window has expired identically to one that was just activated.
- **Pause blocks `cancel_match`:** `lib.rs:644` — the pause mechanism, designed for emergencies, compounds the dead zone when combined with authority inaction
- **No automatic refund:** Players must submit transactions to recover funds; there is no automated on-chain mechanism

## Exploitation Scenario

### Variant A: Passive Grief (Authority Inaction)

**Prerequisites:**
1. Attacker controls the server authority keypair
2. One or more Active matches exist with deposits at the maximum wager (100 SOL each player)
3. Attacker allows the 1-hour settlement window to expire without calling `settle_match`

**Attack Steps:**
1. Authority creates match with high wager: `create_match(match_id, 100_000_000_000, player_one, player_two)`
2. Both players call `deposit_wager`, depositing 100 SOL each. `activated_at` is set.
3. Authority waits until `Clock::get()?.unix_timestamp > activated_at + 3600` — does NOT call `settle_match`
4. Settlement window expires. `settle_match` now returns `SettlementExpired`.
5. Players call `cancel_match` but receive `Unauthorized` — `is_timed_out` is false (< 24h)
6. Players are locked out for 23 hours with no on-chain recourse
7. At `activated_at + 86400`, players can finally call `cancel_match` and recover their deposits

**Impact:** 200 SOL locked per match × number of concurrent matches. At current SOL prices (~$130 USD), a single match = ~$26,000 locked for 23 hours. If 10 concurrent matches = $260,000 locked. Reputational damage to the platform. No fund loss — funds are recovered after 24 hours.

### Variant B: Active Grief (Authority + Pause)

**Prerequisites:**
1. Attacker controls the server authority keypair
2. One or more Active matches exist
3. Settlement window has expired (> 1h post-activation)

**Attack Steps:**
1-3. Same as Variant A
4. Settlement window expires
5. Authority calls `pause_program` (requires authority signer — `lib.rs:480-490`)
6. Players attempt `cancel_match` at the 24-hour mark. `ProgramPaused` error is returned (line 644).
7. Players are forced to wait for `permissionless_reclaim` at 48 hours
8. At `activated_at + 172800`, `permissionless_reclaim` succeeds (no pause guard — DCA-02)

**Impact:** 200 SOL locked per match for up to 47 hours (1h settlement window + 47h pause window before reclaim). Maximum realistic lockup: 48 hours minus 1 second.

### Proof of Concept Outline
1. **Setup:** Deploy program, initialize config, create a match with `wager_lamports = 100_000_000_000`. Both players call `deposit_wager`. Match transitions to Active with `activated_at = T`.
2. **Attack:** Authority key holder takes no action. Let T + 3601 pass. No `settle_match` is called.
3. **Verification:** At T + 3601, both players attempt `cancel_match`. Both receive `EscrowError::Unauthorized`. The escrow account is queryable on-chain and shows state = Active with both `player_one_deposited` and `player_two_deposited` = true, 200 SOL balance, and no outgoing transactions.
4. **Result:** 200 SOL locked. No on-chain instruction can free it until T + 86401.

### Recommended Fix

**Option 1 (Minimal — Recommended for v1.x):** Add an authority-cancel path for Active matches whose settlement deadline has expired.

```rust
// Before (vulnerable) — authority cannot cancel Active matches under any circumstances:
require!(
    (is_authority && escrow_state == MatchState::AwaitingDeposits)
    || (is_player && (escrow_state == MatchState::AwaitingDeposits || is_timed_out)),
    EscrowError::Unauthorized
);

// After (fixed) — authority can cancel Active matches only AFTER settlement deadline expires:
let settlement_deadline = ctx.accounts.escrow.activated_at
    .checked_add(SETTLEMENT_TIMEOUT_SECONDS)
    .ok_or(EscrowError::ArithmeticOverflow)?;
let settlement_expired = Clock::get()?.unix_timestamp > settlement_deadline;

require!(
    (is_authority && (escrow_state == MatchState::AwaitingDeposits
        || (escrow_state == MatchState::Active && settlement_expired)))
    || (is_player && (escrow_state == MatchState::AwaitingDeposits || is_timed_out)),
    EscrowError::Unauthorized
);
```

This closes the dead zone: once the 1-hour settlement window expires, the authority can proactively trigger cancellation and refund players without waiting for the 24-hour player timeout. A griefing authority would still be able to wait (just doing nothing), but an honest authority with a server failure can immediately recover player funds.

**Option 2 (Structural — Recommended for v2.x):** Reduce the player cancellation timeout for Active matches with expired settlement windows. Instead of requiring 24 hours from `activated_at`, allow player cancel at `activated_at + SETTLEMENT_TIMEOUT_SECONDS + GRACE_PERIOD` (e.g., grace period = 30 minutes).

```rust
// Compute which timeout applies based on whether settlement deadline has passed
let cancel_reference = if settlement_expired {
    // Settlement window already closed — players can cancel sooner
    settlement_deadline  // effectively activated_at + 3600
} else {
    activated_at  // full 24h timeout (settlement still possible)
};
let timeout_deadline = cancel_reference
    .checked_add(GRACE_PERIOD_SECONDS)
    .ok_or(EscrowError::ArithmeticOverflow)?;
```

**Option 3 (Transparency — Complementary):** Emit a `SettlementDeadlineExpired` event when `settle_match` is called after the deadline, enabling indexers and players to monitor and react to expired-but-unresolved matches.

## Incidental Discoveries

- **Pause Extends Dead Zone to 48h (Related Griefing Vector):** The interaction between the pause mechanism and `cancel_match`'s pause guard creates a compound attack where a malicious authority can: (1) allow settlement window to expire (hour 1), (2) pause program (blocking `cancel_match` at hour 24), forcing players to wait for `permissionless_reclaim` at hour 48. This is structurally distinct from H006's dead zone and should be investigated as a separate hypothesis. Suggested new hypothesis: "Pause-Amplified Lockup Griefing — authority combines settlement inaction with pause to extend fund lockup from 23h to 47h, exploiting the fact that `cancel_match` checks `!is_paused` but `permissionless_reclaim` does not."

- **Settlement Deadline as Reliability Risk (Not Just Griefing):** The 1-hour window is also a server-reliability risk. If the game server experiences a >1h outage during a match, settlement becomes permanently impossible for that match, forcing the 23-hour dead zone even with an honest authority. On Solana mainnet, network halts (EP-124) have historically lasted multiple hours. If the server's Solana RPC connection fails for > 1 hour while matches are Active, honest players are locked out through no malicious intent. Suggested hypothesis: "Server Outage Settlement Loss — RPC or server downtime > 1h during Active match permanently blocks settlement, triggering unintentional 23-hour fund lockup."

### EP-089 Applicability
EP-089 describes timestamp manipulation where validators can drift clock by ~30 seconds. This is NOT the primary issue for H006. The dead zone is 82,800 seconds (23 hours) — clock manipulation by 30 seconds reduces it to 82,770 seconds, immaterial. EP-089 is not the relevant pattern here. H006 is better described as a **state machine dead zone** — a design gap where no valid state transition exists for a specified time range, rather than a timestamp-manipulation attack.

### Boundary Condition Analysis
The settlement deadline uses `<=` (inclusive): `now <= activated_at + 3600`. The cancellation timeout uses `>` (strict): `now > activated_at + 86400`. There is exactly 1 second at the settlement deadline boundary where both settlement and cancellation are either possible or impossible:
- At `now == activated_at + 3600`: settlement is still possible (`<=`); cancellation not yet possible (`>`)
- At `now == activated_at + 3601`: settlement is impossible; cancellation not yet possible
- Gap: 82,799 seconds (still effectively 23 hours)

The comparison operators are intentionally asymmetric and do not reduce the severity of the finding.

### Authority Restriction Design Intent
The prohibition on authority cancelling Active matches (line 341) is intentional and serves an important purpose: it prevents a colluding authority from cancelling a match to deny the winning player their payout. This is OC-05. The dead zone is a side effect of this protection: by blocking the authority from cancelling Active matches (to prevent abuse), the program also blocks the authority from acting as a good-faith escape valve after settlement expires. Option 1 in the fix section addresses this by allowing authority cancellation ONLY when settlement has already expired — the authority could no longer manipulate the outcome anyway since settlement is impossible.
