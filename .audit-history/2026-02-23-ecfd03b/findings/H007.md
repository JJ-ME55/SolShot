# Finding: H007 - Pause-as-Griefing Attack on Active Matches

## Status: CONFIRMED
## Confidence Score: 9/10

> - **9-10**: Certain — exhaustive code analysis, all paths verified
> - **7-8**: High — strong evidence, minor gaps in coverage
> - **5-6**: Moderate — reasonable analysis, some assumptions unverified

## Executive Summary

The pause-as-griefing attack is fully confirmed. A compromised authority key can call `pause_program`, which sets `config.is_paused = true`. This single flag blocks `settle_match` (line 605) and `cancel_match` (line 644) via Anchor constraint checks, but has no effect on `permissionless_reclaim` which does not load the config account at all (lines 653-681). All Active matches are therefore locked for the full 48-hour permissionless reclaim timeout — neither settlement nor player-initiated cancellation is available during the pause.

The attack cannot steal funds. All deposited SOL will eventually be returned to the correct players via `permissionless_reclaim`. However, the attack delivers maximum fund lockup duration (48 hours), causes irreversible reputational damage, and the attacker can trivially maximize TVL at risk by timing the pause during peak match activity. The authority key is currently a single hot wallet with no multisig protection, meaning key compromise is a realistic precondition.

## Hypothesis Investigated

> A compromised authority can pause the program while active matches exist. Pause blocks settle_match AND cancel_match, but NOT permissionless_reclaim. This forces all active match participants to wait 48 hours for permissionless_reclaim, creating maximum fund lockup.
>
> Attack Vector:
> 1. Attacker compromises authority key
> 2. Multiple matches are in Active state
> 3. Attacker calls `pause_program`
> 4. settle_match blocked (pause guard), cancel_match blocked (pause guard)
> 5. Only escape: permissionless_reclaim after 48h

## Investigation Path

### Step 1: Verify pause guards on settle_match
**Location:** `lib.rs:600-607`
**Finding:** Pause guard confirmed on `SettleMatch` account struct.
**Evidence:**
```rust
/// Config PDA — provides validated treasury/ops/authority pubkeys + pause guard (OC-04)
#[account(
    seeds = [GlobalConfig::SEED],
    bump = config.bump,
    has_one = authority @ EscrowError::Unauthorized,
    constraint = !config.is_paused @ EscrowError::ProgramPaused,  // line 605
)]
pub config: Account<'info, GlobalConfig>,
```
When `config.is_paused == true`, the Anchor constraint at line 605 rejects the instruction with `ProgramPaused` before the handler body executes. Settlement is completely blocked.

### Step 2: Verify pause guards on cancel_match
**Location:** `lib.rs:640-646`
**Finding:** Pause guard confirmed on `CancelMatch` account struct.
**Evidence:**
```rust
/// Config PDA — provides authority pubkey + pause guard (OC-04, OC-05)
#[account(
    seeds = [GlobalConfig::SEED],
    bump = config.bump,
    constraint = !config.is_paused @ EscrowError::ProgramPaused,  // line 644
)]
pub config: Account<'info, GlobalConfig>,
```
When `config.is_paused == true`, the Anchor constraint at line 644 rejects cancel_match. Players cannot exit an Active match during pause regardless of how much time has elapsed.

### Step 3: Verify permissionless_reclaim has NO pause guard
**Location:** `lib.rs:653-681`
**Finding:** Confirmed — `PermissionlessReclaim` struct does not include a `config` account. No pause check is possible.
**Evidence:**
```rust
/// PermissionlessReclaim — anyone can reclaim after 2x timeout (DCA-02)
/// No authority or player check. Caller receives PDA rent as incentive.
#[derive(Accounts)]
pub struct PermissionlessReclaim<'info> {
    #[account(
        mut,
        seeds = [b"match", escrow.match_id.as_bytes()],
        bump = escrow.bump,
        close = caller,
    )]
    pub escrow: Account<'info, MatchEscrow>,

    #[account(mut)]
    pub caller: Signer<'info>,

    // ... only player_one, player_two, system_program follow
    // NO config account — pause cannot be checked
    pub system_program: Program<'info, System>,
}
```
`permissionless_reclaim` is the only economic instruction that does not require the `config` account. Pause is stored exclusively in `config.is_paused`; without loading config, there is no mechanism to enforce the pause. This is noted in `ARCHITECTURE.md` as deliberate design (DCA-02 escape hatch).

### Step 4: Verify the 48-hour lockup duration for Active matches
**Location:** `lib.rs:396-411`
**Finding:** For Active matches (`activated_at > 0`), the timeout reference is `activated_at`. The reclaim deadline is `activated_at + PERMISSIONLESS_RECLAIM_TIMEOUT` where `PERMISSIONLESS_RECLAIM_TIMEOUT = 172800` (48 hours, line 23).
**Evidence:**
```rust
let timeout_reference = if ctx.accounts.escrow.activated_at > 0 {
    ctx.accounts.escrow.activated_at  // uses activation time
} else {
    ctx.accounts.escrow.created_at
};

let reclaim_deadline = timeout_reference
    .checked_add(PERMISSIONLESS_RECLAIM_TIMEOUT)  // 172800s = 48h
    .ok_or(EscrowError::ArithmeticOverflow)?;

require!(
    Clock::get()?.unix_timestamp > reclaim_deadline,
    EscrowError::TooEarlyToReclaim
);
```
The 48-hour timer is anchored to `activated_at`, not to when the pause was invoked. If a match activated 47 hours before the pause, the reclaim becomes available in as little as 1 hour post-pause. However, if a match just activated when the pause lands, participants must wait the full 48 hours.

### Step 5: Verify authority key is a single hot wallet (precondition assessment)
**Location:** `ARCHITECTURE.md`, `lib.rs:691-702`
**Finding:** The `config.authority` field is a single pubkey stored in the GlobalConfig PDA. The context analysis (`01-access-control.md`) confirms it is the server hot wallet: "Server hot wallet is a single point of failure. Compromise = arbitrary settlement, config changes, pause abuse." No multisig protection exists at the on-chain level. The OC-13 note in the source file comments acknowledges this: "transfer upgrade authority to multisig before mainnet deploy."

### Step 6: Verify the attack cannot be reversed by the compromised attacker
**Location:** `lib.rs:70-89` (update_config), `lib.rs:93-103` (pause/unpause)
**Finding:** The attacker who compromises the authority key holds `has_one = authority` access to `pause_program` AND `unpause_program`. After pausing, the attacker could also call `update_config` with `new_authority = Some(attacker_controlled_key)` in the same transaction, permanently locking out the legitimate team from unpausing. Or more simply: the attacker pauses the program, then discards/destroys the compromised key, making unpause impossible. There is no time-limit on how long the pause persists.

### Step 7: Calculate TVL at risk
**Location:** `lib.rs:28-32`
**Finding:** `MAX_WAGER_LAMPORTS = 100_000_000_000` (100 SOL per player, 200 SOL per match). With N concurrent Active matches, TVL at risk = N * 200 SOL. The program has no limit on concurrent active matches. All funds are locked for up to 48 hours each (measured from their respective `activated_at` timestamps).

## Invariant Analysis

### Target Invariant
"Player funds deposited in Active escrow accounts must be accessible (settleable or cancellable) within a reasonable timeframe. A compromised authority must not be able to deny fund access for more than the designed safety window."

### Enforcement Points
| Location | What It Enforces | Complete? |
|----------|-----------------|-----------|
| `lib.rs:605` | Pause blocks settle_match | Yes — applies during pause |
| `lib.rs:644` | Pause blocks cancel_match | Yes — applies during pause |
| `lib.rs:653-681` | Permissionless reclaim has no pause check | Yes — escape hatch works |
| `lib.rs:404-411` | 48h minimum delay before reclaim | Yes — timer anchored to activated_at |

### Enforcement Gap Assessment
The invariant is partially enforced. The 48-hour permissionless reclaim IS the intended safety net for this scenario — the architecture document explicitly identifies this as the designed escape hatch (DCA-02). However, the 48-hour lockup itself is the vulnerability concern: maximum lockup = 48 hours of fund denial per match. For matches activated just before the pause, the full 48-hour window applies.

The gap is not in the escape mechanism (it works correctly) but in the duration and the single-key precondition: a single compromised hot wallet key enables this attack with no on-chain safeguard beyond the 48h reclaim window.

## Blocking Factors
- **Funds are not stolen**: `settle_match` is also blocked during pause; there is no instruction that extracts funds to an unauthorized recipient while paused. All funds eventually return to the depositing players via `permissionless_reclaim`.
- **48-hour cap**: The maximum fund lockup is 48 hours from `activated_at`. This is a hard bound enforced by the timeout arithmetic.
- **Permissionless reclaim works**: Any address (including affected players) can call `permissionless_reclaim` after the 48h deadline. Players do not need the authority to recover funds.
- **Pause requires authority key**: An unauthenticated attacker cannot call `pause_program` (requires `has_one = authority` signer).

## Enabling Factors
- **Single hot wallet authority**: `lib.rs:691-702` — `config.authority` is a single Pubkey with no on-chain multisig. Key compromise is a realistic threat vector (compare: Raydium admin key $4.4M, Pump.fun $1.9M, Upbit $36M — all EP-068/EP-073 class incidents).
- **One-step authority lock-out**: `lib.rs:78-79` — `config.authority = a` is immediate. Attacker can transfer authority to a dead key in the same transaction as the pause, making `unpause_program` permanently inaccessible.
- **No timelock on pause**: Pause takes effect in the same block it is called. No delay, no veto period.
- **pause_program is idempotent**: `lib.rs:93-94` — calling pause when already paused is a no-op. No undo-by-replay mechanism exists.
- **No concurrent match limit**: The program places no cap on how many Active matches can exist simultaneously. TVL at risk scales linearly with protocol adoption.
- **No on-chain monitoring/alerting**: There is no event emitted when `pause_program` is called (no `emit!` in the pause handler). Off-chain monitoring must independently index the transaction to detect a rogue pause.

## Exploitation Scenario

### Prerequisites
1. Attacker obtains the server authority private key (hot wallet compromise, phishing, infrastructure breach, insider threat)
2. Multiple matches are in `Active` state (both players have deposited)
3. Program is currently unpaused (`config.is_paused == false`)

### Attack Steps
1. Attacker (optionally) calls `update_config` with `new_authority = Some(<attacker_dead_key>)` to permanently lock out the legitimate team from unpausing. This takes effect immediately.
2. Attacker calls `pause_program` using the (still valid at this moment) original authority key.
3. All subsequent calls to `settle_match` and `cancel_match` fail with `ProgramPaused`.
4. Affected players have no on-chain recourse until 48h from each match's `activated_at` timestamp.
5. After 48h, any caller can invoke `permissionless_reclaim` and recover funds for affected players.

### Impact
- **Fund lockup**: All Active matches are locked for up to 48 hours. Maximum TVL per match = 200 SOL ($x depending on SOL price). With e.g. 20 concurrent matches, this could be 4,000 SOL locked.
- **Settlement denial**: Even matches with a clear, legitimate outcome cannot be settled. Winners do not receive their winnings; losers do not receive partial refunds.
- **Reputational damage**: A 48-hour fund inaccessibility event on a gaming platform would likely cause permanent user confidence loss.
- **No direct theft**: The attacker cannot redirect funds to themselves. This is a DoS/griefing attack, not a theft attack.

### PoC Transaction Sequence

```
TX 1: update_config
  Accounts: config (PDA ["config"]), authority (original key, signer)
  Args: new_authority = Some(<attacker_controlled_dead_pubkey>)
  Prerequisite: Attacker holds original authority private key
  Result: config.authority is now an attacker-controlled/dead key.
          The original authority key can no longer call unpause_program.

TX 2: pause_program
  Accounts: config (PDA ["config"]), authority (original key, signer — still valid
            because the has_one check on PauseProgram reads the OLD config.authority
            from the account... but wait — TX 1 already changed config.authority.
            CORRECTION: TX 1 and TX 2 must be in the same transaction, OR
            TX 2 must be sent BEFORE TX 1, OR the attacker must use the NEW
            authority key for TX 2 if TX 1 changes authority first.)

REVISED SEQUENCE (simpler approach):

TX 1: pause_program
  Accounts: config (PDA ["config"]), authority (compromised key, signer)
  Args: (none)
  Prerequisite: Attacker holds config.authority private key; config.is_paused == false
  Result: config.is_paused = true

TX 2 (optional hardening): update_config
  Accounts: config (PDA ["config"]), authority (compromised key, signer)
  Args: new_authority = Some(<dead_pubkey_nobody_controls>)
  Prerequisite: TX 1 landed; attacker still holds original authority key
  Result: config.authority is now an uncontrolled key; unpause_program is forever blocked

--- 48h elapses ---

TX 3: permissionless_reclaim (called by player or any third party)
  Accounts: escrow (affected match PDA), caller (any signer), player_one, player_two, system_program
  Args: (none)
  Prerequisite: Clock::get()?.unix_timestamp > escrow.activated_at + 172800
  Result: escrow.state = Cancelled; both players refunded their wager_lamports;
          caller receives PDA rent (~0.00146 SOL)

Final State: All Active match funds locked for up to 48h from respective activated_at.
No settlement occurred. Winners and losers receive equal refunds regardless of match outcome.
Reputational damage persists. If TX 2 was executed, the program's governance is permanently
broken (no new matches, no config changes, no unpause possible).
```

### Proof of Concept Outline
1. **Setup:** Obtain server authority private key. Wait for multiple matches to enter Active state (both players deposited). Confirm with on-chain state.
2. **Attack:** Submit `pause_program` signed by authority key. Optionally follow with `update_config(new_authority=dead_key)` to prevent recovery.
3. **Result:** All Active match funds locked. `settle_match` and `cancel_match` fail with `ProgramPaused`. No resolution available until 48h deadline per match.

### Recommended Fix

The root cause is the combination of: (1) single-key authority with no multisig, and (2) pause affecting cancel_match (which protects player funds, not protocol integrity). Two complementary fixes address different aspects:

**Fix A — Multisig authority (highest priority, off-chain/deployment)**
Transfer `config.authority` to a multisig (e.g., Squads Protocol) before mainnet. This raises the bar for key compromise from "steal one key" to "steal M-of-N keys."

**Fix B — Allow cancel_match while paused (on-chain, changes trust model)**
Remove the pause guard from `cancel_match`. Players should always be able to exit a match, even during emergency pause. Pause's purpose is to halt NEW economic activity, not to trap existing depositors.

```rust
// Before (vulnerable — cancel_match is pause-gated)
// CancelMatch account struct, lib.rs:640-646:
#[account(
    seeds = [GlobalConfig::SEED],
    bump = config.bump,
    constraint = !config.is_paused @ EscrowError::ProgramPaused,  // THIS LINE
)]
pub config: Account<'info, GlobalConfig>,

// After (fixed — remove pause constraint from cancel_match)
// CancelMatch account struct:
#[account(
    seeds = [GlobalConfig::SEED],
    bump = config.bump,
    // No pause guard — players can always cancel to protect their funds
)]
pub config: Account<'info, GlobalConfig>,
```

With Fix B applied, a compromised authority can still pause the program (blocking new match creation and settlement), but players can cancel at any time, recovering funds within minutes rather than 48 hours. This reduces the maximum fund lockup from 48h to the existing 24h player cancel timeout — and if the player acts immediately, effectively zero.

**Fix C — Emit event on pause (monitoring/detection)**
```rust
// In pause_program handler (lib.rs:93-95):
pub fn pause_program(ctx: Context<PauseProgram>) -> Result<()> {
    ctx.accounts.config.is_paused = true;
    emit!(ProgramPaused { authority: ctx.accounts.authority.key() });  // ADD THIS
    Ok(())
}
```
This makes rogue pauses detectable by on-chain event indexers within seconds, allowing the team to respond and alert users before significant TVL accumulates.

## Incidental Discoveries
- **No emit on pause_program**: The `pause_program` handler (line 93-95) does not emit any event. An emergency pause is a high-severity operational event that should be logged on-chain for monitoring. Similarly, `unpause_program` (line 100-102) has no event. Suggested new hypothesis: **"Silent pause — is the absence of pause/unpause events a monitoring blind spot that extends attacker dwell time?"** → Investigate whether on-chain monitoring can detect rogue pauses through transaction-level indexing alone, or if the lack of events creates a meaningful detection gap.

- **pause_program allows calling update_config in same transaction**: An attacker who calls `pause_program` then immediately `update_config(new_authority=dead_key)` in the same transaction atomically achieves both maximum lockup AND permanent governance destruction. Since these two calls are in the same transaction, there is no window for the legitimate team to detect and respond between them. This deserves separate consideration as an atomic compound attack.

### Authority key compromise realism
The exploit-patterns index notes several real incidents of single-key authority compromise on Solana: Raydium admin key ($4.4M, EP-068/EP-073), Pump.fun ($1.9M, EP-068/EP-094), Upbit Solana hot wallet ($36M, EP-068/EP-097), Step Finance ($30-40M, EP-068/EP-097). The pattern is well-established and the precondition (compromised authority) is realistic for a server hot wallet that signs transactions continuously.
