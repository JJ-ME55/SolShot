# Finding: H004 — S004 RECHECK — Verify CreateMatch `has_one = authority` Fix

## Status: NOT VULNERABLE (FIXED in v1 and v2)
## Confidence Score: 10/10

> - **9-10**: Certain — exhaustive code analysis, all paths verified

## Executive Summary

S004 was the February audit's CRITICAL finding (CVSS 9.3): the `CreateMatch` account struct lacked `has_one = authority` on the config account, allowing any funded wallet to pre-squat match PDA slots and silently void wager escrows. The fix — adding `has_one = authority @ EscrowError::Unauthorized` to `CreateMatch.config` — was applied in v1 and correctly carried over to v2. Both programs now enforce that only `config.authority` can create `MatchEscrow` PDAs. No bypass exists.

This fix also fully subsumes Feb H008 (PDA Occupancy DoS), which identified the same missing gate from a different attack angle. Both findings reduce to the single absent constraint, now present in both programs.

## Hypothesis Investigated

S004 (CRITICAL, CVSS 9.3): `create_match` lacked `has_one = authority`, so any signer could pre-occupy a match PDA before the legitimate server. Combined with the public `setRooms` broadcast (which reveals exact roomIds) and a long frontrun window (room creation → second player joins), this was a zero-cost, fully sustainable DoS that silently dropped all wager escrows. Fix required: add `has_one = authority @ EscrowError::Unauthorized` to `CreateMatch.config`.

## Investigation Path

### Step 1: v1 CreateMatch struct — confirm fix at line 625

**Location:** `programs/solshot-escrow/src/lib.rs:606-631`

**Finding:** Fix is present. The `has_one = authority @ EscrowError::Unauthorized` constraint is on the config account at line 625, and `authority: Signer<'info>` is declared at line 619. Anchor cross-references these two: the signing key must equal `config.authority`, otherwise the transaction is rejected with `Unauthorized`.

**Evidence:**
```rust
// v1:618-628
#[account(mut)]
pub authority: Signer<'info>,

/// Config PDA — provides pause guard + authority gate (OC-04, S004)
#[account(
    seeds = [GlobalConfig::SEED],
    bump = config.bump,
    has_one = authority @ EscrowError::Unauthorized,      // ← S004 fix
    constraint = !config.is_paused @ EscrowError::ProgramPaused,
)]
pub config: Account<'info, GlobalConfig>,
```

Comment references `S004` explicitly, confirming intentional placement.

### Step 2: v2 CreateMatch struct — confirm equivalent constraint at line 659

**Location:** `programs/solshot-escrow-v2/src/lib.rs:641-665`

**Finding:** Identical constraint is present at v2:659 with the same error variant.

**Evidence:**

### Step 3: Verify `Signer<'info>` requirement on authority in both structs

- v1:619 — `pub authority: Signer<'info>` — Anchor enforces the signing key before evaluating `has_one`.
- v2:654 — `pub authority: Signer<'info>` — same.

The two-layer check is: (a) the presented key must have signed the transaction (Signer), (b) that key must equal `config.authority` (has_one). Both conditions must hold. Neither alone is sufficient; together they are complete.

### Step 4: Verify config PDA is canonically derived (no substitution)

- v1:622-624: `seeds = [GlobalConfig::SEED], bump = config.bump` — Anchor re-derives the config PDA and rejects any account whose address doesn't match.
- v2:657-658: identical seed and bump validation.

An attacker cannot substitute a fake config account that stores their own pubkey as `authority`, because the PDA address would differ from the canonical `["config"]` PDA.

### Step 5: Test for bypass — can a third-party create a match?

Attempting to reason through every bypass angle:

| Bypass Attempt | Why It Fails |
|----------------|--------------|
| Sign `create_match` with a non-authority key | `has_one = authority` compares `config.authority` against the signer; mismatch → `Unauthorized` error |
| Substitute a different config account | Anchor's PDA seed re-derivation rejects any account not at `["config"]` address |
| Pass authority as a non-signer | `Signer<'info>` type requires a signature; absent signature → transaction-level rejection |
| Exploit pause to bypass | Pause guard is `!config.is_paused`, additive — it does not weaken the authority gate |
| Exploit a permissionless reclaim to "settle" an attacker-created escrow | `settle_match` has `has_one = authority` on both escrow AND config (v1:664, v1:703); attacker's escrow would have `escrow.authority = attacker_key`, not `config.authority` — settle would fail |

No bypass path exists. The invariant — "only config.authority can create MatchEscrow PDAs" — is completely enforced.
