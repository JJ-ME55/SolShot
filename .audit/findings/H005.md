# Finding: H005 — H008 RECHECK — CreateMatch PDA Occupancy DoS

## Status: NOT VULNERABLE (SUBSUMED — closed by S004/H004 fix)
## Confidence Score: 10/10

> - **9-10**: Certain — exhaustive code analysis, all paths verified

**One-line summary:** Feb H008 (PDA Occupancy DoS via third-party `create_match`) is fully subsumed by the S004 fix (`has_one = authority @ EscrowError::Unauthorized` on `CreateMatch.config`); `create_match` is authority-gated in both v1 (line 625) and v2 (line 659), making third-party PDA squatting impossible.

---

## Executive Summary

The February audit's H008 finding identified that the absence of an authority gate on `CreateMatch.config` allowed any funded wallet to pre-occupy a match PDA using a known `match_id`, silently voiding wager escrows before the server could create them. The root cause was identical to S004 (CRITICAL, CVSS 9.3): the missing `has_one = authority` constraint.

The S004 fix — adding `has_one = authority @ EscrowError::Unauthorized` to `CreateMatch.config` — was applied in v1 at line 625 and carried forward into v2 at line 659. Both programs require the signer to be `config.authority` before a `MatchEscrow` PDA can be initialised. The H008 attack path is completely blocked. No separate remediation is required; H008 is closed by the same patch as S004, as confirmed in H004.

---

## Hypothesis Investigated

**Feb H008 (HIGH):** A third-party (non-authority) attacker monitors the server's `setRooms` broadcast to learn upcoming `match_id` values, then races to call `create_match` with their own keypair before the server does. Anchor's `init` constraint prevents double-initialisation, so the server's subsequent `create_match` fails with `AccountAlreadyInitialized`. The attacker's PDA stores an attacker-controlled `players[]` array. All deposit transactions from legitimate players are silently dropped because the escrow's state machine is under attacker control. Net result: all wagered matches are unescrowable for as long as the attacker sustains the attack at zero cost beyond rent (recoverable via `close`).

## Investigation Path

### Step 1: Confirm `has_one = authority` on CreateMatch.config in v1

**Location:** `programs/solshot-escrow/src/lib.rs:606-631`

**Finding:** Fix is present. `authority: Signer<'info>` at line 619 authenticates the signer. `has_one = authority @ EscrowError::Unauthorized` at line 625 requires the signing key to equal `config.authority`. Both conditions must hold simultaneously.

**Evidence:**
```rust
// v1:618-628
#[account(mut)]
pub authority: Signer<'info>,

/// Config PDA — provides pause guard + authority gate (OC-04, S004)
#[account(
    seeds = [GlobalConfig::SEED],
    bump = config.bump,
    has_one = authority @ EscrowError::Unauthorized,      // ← S004 fix (closes H008)
    constraint = !config.is_paused @ EscrowError::ProgramPaused,
)]
pub config: Account<'info, GlobalConfig>,
```

### Step 2: Confirm equivalent constraint in v2

**Location:** `programs/solshot-escrow-v2/src/lib.rs:641-665`

**Finding:** Identical two-layer check at v2:654 (`Signer<'info>`) and v2:659 (`has_one = authority`). No gap introduced in the v2 rewrite.

**Evidence:**
```rust
// v2:653-662
#[account(mut)]
pub authority: Signer<'info>,

#[account(
    seeds = [GlobalConfig::SEED],
    bump = config.bump,
    has_one = authority @ EscrowError::Unauthorized,      // ← inherited fix
    constraint = !config.is_paused @ EscrowError::ProgramPaused,
)]
pub config: Account<'info, GlobalConfig>,
```

### Step 3: Verify config PDA cannot be substituted

Both versions enforce `seeds = [GlobalConfig::SEED], bump = config.bump`. Anchor re-derives the config PDA on every call and rejects any account whose address does not match. An attacker cannot substitute a fake config account storing their own pubkey as `authority`.

## Attack Path Analysis

| Step | Required Action | Possible? | Blocking Factor |
|------|-----------------|-----------|-----------------|
| 1 | Monitor `setRooms` to learn match_id | Yes (server broadcast) | No block needed — knowledge alone is harmless |
| 2 | Call `create_match` with attacker keypair | **No** | `has_one = authority` at v1:625 / v2:659 — signer must equal `config.authority`; attacker key ≠ stored authority → `Unauthorized` |
| 3 | Occupy PDA before server | **No** | Step 2 is impossible; attack chain is broken at first barrier |

## Invariant Analysis

### Target Invariant
Only `config.authority` can cause a `MatchEscrow` PDA to be initialised.

### Enforcement Points

| Location | What It Enforces | Complete? |
|----------|-----------------|-----------|
| `v1:619` / `v2:654` — `authority: Signer<'info>` | Signing key is authenticated at transaction level | Yes |
| `v1:625` / `v2:659` — `has_one = authority @ Unauthorized` | Signing key must equal stored `config.authority` | Yes |
| `v1:622-624` / `v2:657-658` — PDA seed re-derivation | Config account cannot be substituted by attacker | Yes |

There is exactly one code path where a `MatchEscrow` PDA is initialised (`create_match`). No `realloc` or alternative init path exists in either program. The invariant is enforced completely on that sole path.
