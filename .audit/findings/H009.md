## Summary

On v1 only, a compromised authority can execute a three-step coup: **pause** → **rotate authority/config** → **unpause** to perform hostile actions (treasury hijack, winner fraud, fee ratcheting) while preventing player exit via `cancel_match`. v2 fixes this by removing the pause guard from `cancel_match`, providing an escape hatch even when paused.

## Attack Chain (v1 only)

```
1. Authority pauses program
   → cancel_match() blocked at CancelMatch.config constraint:
     constraint = !config.is_paused @ EscrowError::ProgramPaused

2. Authority rotates config
   → update_config(new_treasury=attacker_wallet, new_ops=attacker_wallet)
   → v1 settle_match reads LIVE config (not snapshot) at line 314:
     let treasury_key = ctx.accounts.treasury.key();  // reads config.treasury

3. Authority unpauses program
   → settles matches in favor of attacker
   → 100% of fees + attacker-favored pot splits flow to compromised wallets
   → players cannot cancel (step 1 pause) until unpause

4. Optional: authority re-pauses and repeats
```

## Verification

### Condition 1: v1 cancel/settle/start_with_depositors have `!is_paused` constraint ✓

**v1 CancelMatch** (line 768):
```rust
#[account(
    seeds = [GlobalConfig::SEED],
    bump = config.bump,
    constraint = !config.is_paused @ EscrowError::ProgramPaused,
)]
pub config: Account<'info, GlobalConfig>,
```
✓ **CONFIRMED** — `cancel_match` is pause-blocked.

**v1 SettleMatch** (line 722):
```rust
#[account(
    ...
    constraint = !config.is_paused @ EscrowError::ProgramPaused,
)]
pub config: Account<'info, GlobalConfig>,
```
✓ **CONFIRMED** — `settle_match` is pause-blocked.

**v1 StartWithDepositors** (line 801):
```rust
constraint = !config.is_paused @ EscrowError::ProgramPaused,
```
✓ **CONFIRMED** — `start_with_depositors` is pause-blocked.

### Condition 2: pause + update_config sequence is possible ✓

**pause_program** (line 112):
```rust
pub fn pause_program(ctx: Context<PauseProgram>) -> Result<()> {
    ctx.accounts.config.is_paused = true;
    Ok(())
}
```
Idempotent, no constraint preventing re-pause or sequential actions.

**update_config** (line 72-108):
- Has NO pause guard in its constraint set.
- Only requires `has_one = authority`.
- Authority can rotate treasury/ops/authority itself while paused.

✓ **CONFIRMED** — pause + update_config is a valid atomic sequence.

### Condition 3: v1 settle reads LIVE config (not snapshot) ✓

**v1 settle_match** (line 314):
```rust
let treasury_key = ctx.accounts.treasury.key();
```
Then later (line 349-350):
```rust
#[account(
    mut,
    constraint = treasury.key() == config.treasury @ EscrowError::InvalidTreasury,
)]
pub treasury: UncheckedAccount<'info>,
```

The treasury account is validated AGAINST `config.treasury` at the moment of `settle_match` call.
If `config.treasury` was rotated by a prior `update_config` call BEFORE this `settle_match`, the settlement uses the NEW (attacker) treasury address.

✓ **CONFIRMED** — v1 reads live config; settlement is vulnerable to mid-sequence hijack.

### Condition 4: v2 is immune (cancel/settle pause-immune) ✓

**v2 CancelMatch** (line 743-765 in `solshot-escrow-v2/src/lib.rs`):
```rust
pub struct CancelMatch<'info> {
    // NO constraint = !config.is_paused
    // Comment at v2:756 — "Pause does NOT block cancel"
}
```

**v2 SettleMatch** (line 706-727):
```rust
pub struct SettleMatch<'info> {
    // NO constraint = !config.is_paused
}
```

**v2 settle_match** (line 434-441):
Reads `escrow.treasury_snapshot` (copied atomically at create_match), NOT live config.

✓ **CONFIRMED** — v2 cancel/settle are pause-immune; snapshot prevents mid-sequence hijack.

## Impact

| Attack | v1 Impact | v2 Mitigation | Residual Risk |
|--------|-----------|---------------|---------------|
| Treasury hijack during pause window | **CRITICAL** — all settle fees redirect to attacker | Per-match snapshot at create_match | NEW matches post-compromise still use live config (H001 root cause) |
| Player exit denial | **HIGH** — cancel_match blocked; only permissionless_reclaim after 1200s timeout | cancel_match immune to pause | Permissionless_reclaim still works (H007 fix in v2) |
| Winner fraud | **CRITICAL** — authority can settle to attacker wallet while players are locked | No mitigation (design choice) | Authority-as-oracle is fundamental |

## Severity Assessment

**v1**: HIGH POTENTIAL (requires authority compromise, but three-step chain is technically valid on-chain)
**v2**: N/A (cancel/settle are pause-immune; chain is broken at step 1)

## Recommended Fixes

### For v1 (if kept in production):
1. **H016-equivalent**: Remove `constraint = !config.is_paused` from `CancelMatch` to allow player exit during pause.
2. **H001-equivalent**: Add `pending_authority` + two-step confirm to prevent instant authority rotation.

### For v2 (already fixed):
- Cancel/settle bypass pause intentionally (comment at v2:756 confirms deliberate H007 fix).
- Per-match snapshot mitigates fee hijack for in-flight matches.

---

**One-line summary:** v1 pause → rotate → unpause chain allows authority coup while blocking player exit; v2 fixes by making cancel pause-immune + per-match snapshot for in-flight fee stability.
