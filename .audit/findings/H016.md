# Finding: H016 — H007 Recheck — Pause-as-Griefing on v1 cancel_match

## Status: CONFIRMED on v1, FIXED on v2
## Confidence Score: 10/10

> Confidence scale:
> - **9-10**: Certain — exhaustive code analysis, all paths verified

## Executive Summary

v1 `cancel_match` retains the `constraint = !config.is_paused` pause guard at `v1:729`. When a compromised authority calls `pause_program`, all deposited players are locked out of `cancel_match` and `settle_match` simultaneously. The only exit path is `permissionless_reclaim`, which carries no config account and is therefore pause-immune. With the current v1 constant `PERMISSIONLESS_RECLAIM_TIMEOUT = TIMEOUT_SECONDS * 2 = 1200s`, the maximum lockup horizon is **20 minutes** — a substantial improvement from the Feb 2026 finding of 48 hours, but still a confirmed griefing window.

v2 explicitly removed the pause guard from `cancel_match` and `settle_match`. The `pause_program` docstring at `v2:144-145` documents this design intent: "Settle / cancel / permissionless_reclaim remain callable so in-flight funds can exit." H007 is FIXED in v2.

## Hypothesis Investigated

Three Phase 1 agents (State Machine, Access Control, Timing) independently converge: v1 pause guard on `cancel_match` blocks all player exit paths except the time-bounded `permissionless_reclaim`; v2 removes it. Verify and write the finding.

## Invariant Analysis

### Target Invariant
"Deposited player funds must always have an accessible exit path, regardless of program pause state."

### Enforcement Points
| Location | What It Enforces | Complete? |
|----------|-----------------|-----------|
| `v1:729` | Pause blocks cancel | **Gap** — players cannot exit while paused |
| `v1:704` | Pause blocks settle | **Gap** — authority cannot settle while paused |
| `v1:739-754` | No config in PermissionlessReclaim | YES — escape hatch is pause-immune |

### Enforcement Gap Assessment
The invariant is violated in v1 for up to 20 minutes post-pause. v2 closes the gap completely: neither cancel nor settle has a pause guard, so funds can always exit immediately via cancel or via permissionless reclaim (which has no pause guard in either version).

## Exploitation Scenario

### Prerequisites
1. Attacker compromises the server authority private key (single hot wallet, `HPyV...nokv`).
2. One or more matches are in `Active` or `AwaitingDeposits` state with deposited funds.

### Attack Steps
1. Attacker calls `pause_program` (signs with compromised authority key).
2. `config.is_paused = true` takes effect in the same block.
3. Players attempt `cancel_match` — rejected with `ProgramPaused` at v1:729.
4. Authority attempts `settle_match` — also rejected with `ProgramPaused` at v1:704.
5. Funds locked until `activated_at + 1200s` (20 minutes), at which point `permissionless_reclaim` becomes callable by anyone.

### Impact
- **Fund lockup**: Up to 20 minutes per active match (bounded by `PERMISSIONLESS_RECLAIM_TIMEOUT = 1200s`).
- **Settlement denial**: Legitimate match winners cannot receive winnings during lockup.
- **No direct theft**: Attacker cannot redirect funds to themselves while paused.
- **Grieving without profit**: The attack imposes inconvenience and potential reputation damage, but the economic blast radius is limited by the 20-minute cap.

### PoC Transaction Sequence
```
TX 1: pause_program
  Accounts: config (PDA [b"config"]), authority (compromised key, signer)
  Args: (none)
  Prerequisite: Attacker holds config.authority private key
  Result: config.is_paused = true

--- Players attempt cancel_match → fail: ProgramPaused at v1:729 ---
--- Authority attempts settle_match → fail: ProgramPaused at v1:704 ---

--- up to 1200s (20 min) elapses ---

TX 2: permissionless_reclaim
  Accounts: escrow (match PDA), caller (any signer), remaining_accounts = deposited players
  Args: (none)
  Prerequisite: Clock::unix_timestamp > escrow.activated_at + 1200
  Result: escrow.state = Cancelled; deposited players refunded; caller receives PDA rent

Final State: Funds locked for ≤20 minutes. No settlement. Match outcome lost.
```

## Fix Recommendation for v1

Mirror the v2 fix: remove the pause constraint from `CancelMatch` in v1.

```rust
// Before (vulnerable) — programs/solshot-escrow/src/lib.rs:725-731
/// Config PDA — provides authority pubkey + pause guard (OC-04, OC-05)
#[account(
    seeds = [GlobalConfig::SEED],
    bump = config.bump,
    constraint = !config.is_paused @ EscrowError::ProgramPaused,  // REMOVE THIS LINE
)]
pub config: Account<'info, GlobalConfig>,

// After (fixed — mirrors v2:755-761)
/// Config PDA — provides authority pubkey for the is-authority check.
/// Pause does NOT block cancel so in-flight funds can always exit.
#[account(
    seeds = [GlobalConfig::SEED],
    bump = config.bump,
    // No pause guard
)]
pub config: Account<'info, GlobalConfig>,
```

Additionally, consider removing the pause guard from v1 `settle_match` (v1:704) to fully mirror v2's "always-exit" principle. v2 removes pause from both cancel AND settle; v1 still blocks settle. Blocking settle while paused prevents attacker-controlled settlement, which could be considered a secondary safety benefit — but it also means legitimate winners are denied their payout during a rogue pause.
