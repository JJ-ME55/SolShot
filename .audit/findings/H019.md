# H019: GlobalConfig Re-initialization Guard

**Status:** NOT_VULNERABLE

## Verification

Both account structs enforce the Anchor `init` constraint (not `init_if_needed`):

- **InitializeConfig** (line 547): `#[account(init, payer = payer, space = GlobalConfig::SPACE, seeds = [GlobalConfig::SEED], bump)]`
- **CreateMatch** (line 610): `#[account(init, payer = authority, space = MatchEscrow::SPACE, seeds = [b"match", match_id.as_bytes()], bump)]`

## Anchor Behavior

The `init` constraint performs:
1. Account existence check — rejects if already initialized
2. Allocates space via system_program::allocate
3. Sets owner to program_id
4. Emits `AccountAlreadyInitialized` on re-init attempts

## Conclusion

Anchor 0.30+ automatically enforces `AccountAlreadyInitialized` error when `init` is used. GlobalConfig and MatchEscrow PDAs cannot be re-initialized after first call. Feb H022 dismissal still holds.
