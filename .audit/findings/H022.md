# H022: GlobalConfig Re-Initialization

**Status:** NOT VULNERABLE
**Severity:** N/A
**Anchor Constraint:** `init` — prevents re-init

## Finding

The `initialize_config` instruction uses Anchor's `#[account(init, ...)]` constraint (line 449), which **prevents account recreation**. Once the PDA at seed `["config"]` exists, the `init` constraint will reject any subsequent `initialize_config` call with an "account already exists" error.

Additionally, there is **no `init_if_needed` variant** and **no mechanism to close the config PDA**. The config account is permanent once created.

## Mechanism

```rust
// Line 446-461: InitializeConfig context
#[derive(Accounts)]
pub struct InitializeConfig<'info> {
    #[account(
        init,              // ← Anchor's `init` constraint: account must NOT exist
        payer = payer,
        space = GlobalConfig::SPACE,
        seeds = [GlobalConfig::SEED],
        bump,
    )]
    pub config: Account<'info, GlobalConfig>,
    ...
}
```

Anchor's `init` constraint:
- Fails if account already exists at PDA `["config"]`
- Cannot be bypassed with `init_if_needed` (not used here)
- No re-init vector available

## Conclusion

**No vulnerability.** Authority re-initialization is impossible. The single-initialization design is sound.

---

**Hypothesis resolved:** The `init` constraint is sufficient to prevent re-init attacks.
