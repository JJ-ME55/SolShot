# H027 — Atomic-TX Rollback Under Anchor 0.32.1

**Status:** NOT_VULNERABLE

## Summary

Verified that Solana transaction rollback semantics remain atomic under Anchor 0.32.1. All lamport transfers in `settle_match`, `cancel_match`, and `permissionless_reclaim` use `?` error propagation, guaranteeing all-or-nothing execution.

## Verification

### settle_match (6 sequential transfers)
Lines 315–326 in `lib.rs`:
- 3 debit operations: `try_borrow_mut_lamports()? -= winner_amount`, `treasury_amount`, `ops_amount`
- 3 credit operations: corresponding `+= ` calls
- All use `?` operator for error propagation
- State write (line 311: `escrow.state = MatchState::Settled`) occurs BEFORE transfers

### cancel_match (variable-length loop)
Lines 404–415 in `lib.rs`:
- Loop refunds N deposited players via `remaining_accounts`
- Each iteration: `try_borrow_mut_lamports()? -= wager_lamports` and corresponding `+=`
- All use `?` propagation
- State set to `MatchState::Cancelled` at line 388 BEFORE loop

### permissionless_reclaim (variable-length loop)
Lines 464–475 in `lib.rs`:
- Identical loop structure to `cancel_match`
- All transfers use `?` for error propagation
- State set at line 459 BEFORE loop

## Atomic Semantics

**Anchor 0.32.1 unchanged:** Solana's runtime guarantees:
- Any `?` error in instruction → full instruction rollback
- All state mutations (including escrow state + lamport deltas) revert
- No partial settlement possible
- This is **protocol-level** (not Anchor-level) behavior — unaffected by Anchor version

## Defense: OC-10 Pattern

State is set to terminal (`Settled` or `Cancelled`) BEFORE any lamport movement:
- If transfer fails → atomically rolls back state + transfers
- If transfer succeeds → state + transfers both commit
- Eliminates race windows (e.g., external observer seeing `Settled` but lamports not yet moved)

## Conclusion

**H029 (Feb 18) dismissal stands. No vulnerability.** Atomic TX rollback is guaranteed and correctly applied.
