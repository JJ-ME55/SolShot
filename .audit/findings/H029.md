# H029: Asymmetric Pot-vs-Mask Scaling

**Status:** NOT_VULNERABLE  
**Category:** Arithmetic (CPI secondary)  
**Tier:** 3 (Defensive)  

## Hypothesis

v2's `deposits_mask: u8` supports 16 bits but `max_players ≤ 4` (hardcoded). If `count_ones(mask)` could exceed `max_players` due to corrupted state, the refund loop in `cancel_match` and `permissionless_reclaim` could over-debit the escrow PDA.

## Finding

**STRUCTURAL INVARIANT HOLDS.** The mask can never exceed `max_players` bits.

### Evidence

1. **Bit-setting bounded by position():** `deposit_wager` (lib.rs:215-217)
   ```rust
   let player_index = ctx.accounts.escrow.players[..max_players]
       .iter()
       .position(|p| *p == depositor)
       .ok_or(EscrowError::NotAPlayer)?;
   ```
   - `position()` returns `player_index < max_players`
   - Bit is set only if `player_index` exists within `players[0..max_players]`

2. **No other instruction modifies the mask:** Only three instructions touch `deposits_mask`:
   - `deposit_wager`: Sets bits for `player_index < max_players`
   - `start_with_depositors`: Compacts the mask to match the new `max_players` (preserves invariant)
   - No direct mask corruption possible

3. **Refund loop validation:** `cancel_match` (lib.rs:317-331)
   ```rust
   for (i, account) in ctx.remaining_accounts.iter().enumerate() {
       require!(i < max_players, EscrowError::InvalidPlayer);
       let bit_set = (deposits_mask >> i) & 1 == 1;
       require!(bit_set, EscrowError::InvalidPlayer);
   ```
   - Refund loop iterates only up to `max_players`
   - Each refund requires the bit to be set at that position
   - Even if mask had spurious high bits, they'd never be read

4. **Compaction safety:** `start_with_depositors` (lib.rs:349-359)
   ```rust
   for i in 0..max {
       if (deposits_mask >> i) & 1 == 1 {
           new_mask |= 1u8 << j;
           j += 1;
       }
   }
   escrow.max_players = j as u8;
   ```
   - After compaction: `new_mask = (1u8 << j) - 1` (all bits 0..j set, rest 0)
   - Remaining bits in `new_mask` are guaranteed ≤ 4

## Conclusion

The mask is a derived property of player registration. It cannot exceed `max_players` bits through any legitimate instruction path. **Flag as defensive coding best practice** but mark NOT_VULNERABLE.
