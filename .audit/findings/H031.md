# H031 — Rent Extraction via cancel/reclaim (Tier-3 Verification)

**Status**: NOT_VULNERABLE (fund-safety) — Economic leakage only

**Finding Category**: Economic / Operational Cost

---

## Summary

At cancel_match or permissionless_reclaim, the escrow PDA is closed with `close = caller`, sending residual lamports (rent reserve) to the caller, not to the original rent payer (authority at create_match). Authority subsidizes ~0.006 SOL per cancel indefinitely, but pot conservation holds — no net theft occurs.

---

## Rent Computation

**v1 Escrow (deployed)**:
- SPACE = 8 + (4 + 32) + 32 + (4 × 32) + 1 + 8 + 1 + 1 + 8 + 8 + 1 = **232 bytes**
- Solana rent for 232 bytes ≈ **0.0036 SOL** (~361 lamports at 1.55 SOL/year, 2.5 year amortization)

**v2 Escrow (future)**:
- SPACE = 8 + (4 + 32) + 32 + (32 × 10) + 1 + 8 + 2 + 4 + 4 + 32 + 32 + 2 + 2 + 1 + 8 + 8 + 8 + 1 = **509 bytes** (10-player support)
- Solana rent for 509 bytes ≈ **0.0061 SOL** (~610 lamports at 1.55 SOL/year)

---

## Root Cause

`lib.rs:718, 745 (v1)` and `v2:748, 773`:

```rust
// CancelMatch and PermissionlessReclaim account structs
#[derive(Accounts)]
pub struct CancelMatch<'info> {
    #[account(
        mut,
        seeds = [b"match", escrow.match_id.as_bytes()],
        bump = escrow.bump,
        close = caller,  // <-- Rent sent to caller, not authority
    )]
    pub escrow: Account<'info, MatchEscrow>,
    ...
}
```

**Authority pays rent at create_match** (`payer = authority` in CreateMatch struct), but **cannot recover it on cancel** because the PDA closes to the caller.

---

## Economic Impact

1. **Per-cancel subsidy**: Authority loses ~0.006 SOL (v1) to ~0.0061 SOL (v2) per cancel/reclaim.
2. **Motivation**: Small constant; reasonable for DCA-02 (permissionless reclaim incentive).
3. **Attacker scenario**: 
   - Attacker creates a match (authority pays 0.0036 SOL rent).
   - Attacker calls cancel within TIMEOUT_SECONDS.
   - Attacker receives 0.0036 SOL rent.
   - Authority net: **−0.0036 SOL** per cancel.
4. **Volume threshold**: ~278 cancels = ~1 SOL rent drain. Feasible but requires relentless griefing; realistic attack cost likely higher (RPC fees, network congestion).

---

## Pot Conservation (Fund Safety)

**Verified**: Pot conservation holds at all paths.

**cancel_match/permissionless_reclaim refund math**:
- Escrow created with: `initial_rent + (wager × count_ones(deposits_mask))`
- Refunds paid: `wager × num_refunded_players`
- Residual at close: `initial_rent` (all deposited wagers refunded, then rent returned via `close = caller`)

**Result**: No deposited wagers are lost or stolen. Rent is transferred, not wagered funds.

---

## Mitigation Analysis

**Option A — Do Nothing**:
- Rent leakage is O(1) per cancel.
- Reasonable incentive for permissionless_reclaim (caller pays gas, receives rent).
- Authority can pause program to stop griefing if needed.

**Option B — `close = authority` (v2+ only)**:
- Authority recovers rent on cancel.
- Con: Reduces incentive for permissionless_reclaim (caller only gets gas refund, not rent).
- Con: Requires authority or a governance multisig to call permissionless_reclaim to recover rent (centralization).

**Option C — Hybrid Incentive (v2+ only)**:
- Caller receives a fixed fraction (e.g., 50%) of rent as incentive; rest returned to authority.
- Con: Adds complexity; requires recalculating rent-exempt minimum.

**Recommendation**: Accept rent leakage in v1 as documented operational cost. Revisit in v2 via governance snapshot (authority can adjust fee BPS to offset rent drain if needed).
