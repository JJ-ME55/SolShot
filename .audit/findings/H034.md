# H034: MIN_WAGER + Extreme Low BPS = Silent Zero Fees

**Status**: CONFIRMED  
**Severity**: LOW  
**Category**: Authorization / Economic Design  
**Affected Component**: v2 `GlobalConfig`, `update_config`, `settle_match`

---

## Issue

The v2 authority can set `fee_bps_treasury = 0` and `fee_bps_ops = 0` to settle matches with zero fee accrual, paying 100% of the pot to the winner. While intentional (a legitimate feature waiver), this combined with H011 (self-redirect treasury/ops pubkeys) enables differential extraction: the authority can subsidize selected matches (0% BPS for matches where they control a player) and tax others (10% BPS for matches where they are the treasury).

---

## Root Cause

**Constraint verification** (`lib.rs:77-79, 128-131`):
```rust
require!(
    (fee_bps_treasury as u32 + fee_bps_ops as u32) <= MAX_FEE_BPS as u32,
    EscrowError::FeesTooHigh
);
```
- `MAX_FEE_BPS = 1_000` (10%)
- 0 + 0 = 0 ≤ 1_000 → **constraint passes**

**Settlement math** (`lib.rs:365-375`):
```rust
let treasury_amount = (total_pot_128 * treasury_bps as u128 / BPS_DENOMINATOR) as u64;
let ops_amount = (total_pot_128 * ops_bps as u128 / BPS_DENOMINATOR) as u64;
```
- When both BPS = 0, both amounts = 0
- Winner receives **entire pot** (remainder after zero deductions)

---

## Impact

**Authority Capabilities**:
1. Call `update_config` with `new_fee_bps_treasury=0, new_fee_bps_ops=0`
2. Create a match with those zero-fee settings (snapshot at create-time)
3. Settle with winner = a player authority controls
4. Winner receives full pot; treasury/ops receive zero

**Differential Extraction Scenario**:
- Match where authority controls player: set BPS to 0/0 → authority-aligned player gets 100%
- Match where authority is treasury: set BPS to 1000/0 (or other high split) → authority reaps fees
- Over time: selectively subsidize favored players, tax others

---

## Mitigation Status

**Partially mitigated by design intent**: The snapshot mechanism (`fee_bps_*_snapshot` at create-time) prevents mid-flight fee changes on in-flight matches. BPS is immutable post-creation, so a 0/0 setting applies uniformly to all players at settlement time — no hidden manipulation possible within a single match.

**Not mitigated**: Nothing prevents authority from choosing who plays in 0-fee matches or who the treasury is. This is a governance issue, not a code vulnerability.

---

## Recommendation

- **Documentation**: Clearly document that BPS can be set to 0 as an intentional feature to waive fees (e.g., for promotional matches).
- **Monitoring**: Track `ConfigUpdated` events with 0-fee settings in off-chain logs.
- **Governance**: Consider requiring timelock or multi-sig approval for fee configuration changes if centralization risk is unacceptable.
