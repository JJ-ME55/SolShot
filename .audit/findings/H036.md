# H036 — Original H006 Dead Zone Status

**STATUS: STATUS_CHANGED — Feb dead zone RESOLVED, but H035 race window took its place.**

## Summary

The original H006 finding reported a 23-hour dead zone (T+3601 to T+86400) where:
- Feb constants: `TIMEOUT_SECONDS = 86400` (24h), `SETTLEMENT_TIMEOUT_SECONDS = 3600` (1h)
- Gap: Player cancel deadline (T+86400) came AFTER settlement expired (T+3600)
- No escape hatch: players stuck in limbo for ~23 hours

## Current Status (v1:20, v1:26)

**The dead zone is gone.**

```
v1 lib.rs:20  const TIMEOUT_SECONDS: i64 = 600;              // 10 min
v1 lib.rs:26  const SETTLEMENT_TIMEOUT_SECONDS: i64 = 3600;  // 1 hour
```

- Player cancel deadline now: T+600 (10 min)
- Settlement deadline: T+3600 (1 hour)
- Result: `T+600 < T+3600` — cancel is available BEFORE settlement expires

## What Replaced It (H035)

Instead of a dead zone, a **settlement-denial race** appeared:
- From T+601 onwards, a losing player can call `cancel_match` 
- This RACES against the authority's `settle_match` window (T+0 to T+3600)
- Whichever lands first wins (settle wins the match, cancel refunds both)
- No dead zone, but temporal ordering is now adversarial

## Gotcha

**Stale comment trojan horse** (lib.rs:23):
```rust
const PERMISSIONLESS_RECLAIM_TIMEOUT: i64 = TIMEOUT_SECONDS * 2; // 172800 seconds
```
The comment claims "172800 seconds" (48 hours), but the actual value is `600 * 2 = 1200` (20 minutes). Formula was preserved from Feb (when `TIMEOUT_SECONDS = 86400`), but constant was reduced — comment now lies.

## Verdict

H006 as stated is **RESOLVED** — players no longer face 23-hour limbo. But see **H035** for the new temporal race condition that replaced it.
