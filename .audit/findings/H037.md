# H037: Deposit Ordering Asymmetry

**Status:** PARTIAL (improved in v2)  
**Severity:** MEDIUM  
**Category:** Timing & State  

## Summary

First depositor's funds are locked asymmetrically while awaiting subsequent deposits. v1 mitigates via cancel-anytime in AwaitingDeposits. v2 improves with hard deposit deadline but retains pre-window exposure.

## Detail

**v1:** First depositor can cancel without timeout during AwaitingDeposits state (lib.rs:374-378). Once second player deposits, both are refunded together on cancel — creating asymmetry: first depositor must wait for second; second can exit anytime after join.

**v2:** Adds hard cutoff at `created_at + deposit_window_secs` (60s–24h, lib.rs:255-262). Deposits blocked post-window; first depositor can then cancel freely. Worst-case lockup: 48 hours (24h window + 24h grace period, lib.rs:539-549).

## Mitigation Status

- **v1:** ✓ Cancel-anytime avoids indefinite lockup. ✗ Player-to-player ordering risk persists if first waits for flaky second.
- **v2:** ✓ Hard deadline bounds lockup to 48h. ✗ Pre-window exposure unchanged.

## Risk

Low impact for reasonable deposit windows (1–5 min typical). Grows with authority's choice of `deposit_window_secs` (unbounded up to 24h per ASSUMPTION-T5). Unrecoverable if partner never shows and first depositor trusts the window.
