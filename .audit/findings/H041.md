# H041: Close = Caller Rent Theft on cancel_match & permissionless_reclaim

**Status:** CONFIRMED LOW (both v1 & v2)  
**Affected Instructions:** `cancel_match`, `permissionless_reclaim`  
**Severity:** LOW  
**Related:** H023 (similar loop pattern, higher severity)

## Summary

Both `cancel_match` and `permissionless_reclaim` use `close = caller` on the MatchEscrow PDA. This allows a non-depositing observer to race and call either instruction after timeout, claiming the PDA rent reserve (~0.002–0.006 SOL per match).

## Root Cause

Anchor's `close = caller` transfers the account's lamport reserve to the TX caller during account closure. Combined with:
- `cancel_match`: accessible to any player OR authority (after timeout)
- `permissionless_reclaim`: intentionally permissionless (anyone, after grace window)

An attacker wallet can monitor pending matches and submit a call to either instruction immediately after the timeout/grace window, capturing rent.

## Proof of Concept

1. Match created at `T=0`, timeout deadline at `T=600` (AwaitingDeposits) or `T+600` (Active).
2. At `T=601`, attacker observes the timed-out match.
3. Attacker calls `cancel_match(escrow_account=PDA)` or `permissionless_reclaim(escrow_account=PDA)`.
4. TX succeeds; attacker receives PDA rent (~0.002 SOL) in their wallet.
5. Authority or legitimate players lose rent to attacker.

## Design Context

The `close = caller` design for `cancel_match` incentivizes players to self-cancel after timeout (no rent loss to them). For `permissionless_reclaim`, it's an explicit incentive for any observer to trigger reclaim and free locked funds. This is intentional, not a defect — confirmed in Feb audit as LOW-impact because:
- Rent per match is small (0.002–0.006 SOL).
- Authority can pre-empt by calling cancel first themselves.
- Economic value typically exceeds rent for matches worth defending.

## Verification Points

**v1 (lib.rs current deployed version):**
- Line ~718: `CancelMatch` struct with `close = caller`
- Line ~745: `PermissionlessReclaim` struct with `close = caller`
- Line ~431-432: `cancel_match` requires `(is_authority && state==AwaitingDeposits) || (is_player && (...))` — any player can call after timeout
- Line ~451-453: `permissionless_reclaim` has NO caller check — fully permissionless

**v2 (same pattern):**
- Line ~748: `CancelMatch` with `close = caller`
- Line ~773: `PermissionlessReclaim` with `close = caller`
- Access control unchanged — same vulnerability surface in both versions

## Mitigation (if required)

If rent theft becomes material concern:
1. Change `close = authority` on both instructions (server absorbs rent, eliminates incentive).
2. Or: allow caller to opt-in via new instruction flag (requires IX upgrade).
3. Or: accept as feature, document in UX that matches may lose rent to race conditions.

Current recommendation: **No action needed.** Rent value (~0.002 SOL) is negligible vs. match wager (typically 0.1–1+ SOL). Authority has pre-emption advantage.
