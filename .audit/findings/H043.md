id: H043
title: Idempotent Pause Emits No Event
severity: LOW
status: CONFIRMED
affected_versions: [v1, v2]
---

## Overview

Both `pause_program` and `unpause_program` instructions are idempotent and emit **no events** when called. This prevents off-chain state-change tracking via event-replay.

## Technical Details

**v1 lines 112-122:**
```rust
pub fn pause_program(ctx: Context<PauseProgram>) -> Result<()> {
    ctx.accounts.config.is_paused = true;
    Ok(())
}

pub fn unpause_program(ctx: Context<UnpauseProgram>) -> Result<()> {
    ctx.accounts.config.is_paused = false;
    Ok(())
}
```

**v2 lines 146-154:** Identical pattern — no event emission.

The instructions set a boolean flag with **zero event logging**. Contrast with `update_config`, which emits `ConfigUpdated` events (`v1:101-105`, `v2:133-139`).

## Operational Impact

1. **Event-replay gap:** Off-chain indexers and monitoring systems cannot reliably track pause/unpause transitions via Solana event logs. They must poll the live `GlobalConfig.is_paused` field.
2. **Silent state changes:** An authority can call `pause_program` 1000 times in a row, each call is a tiny CU cost, and there is zero observable signal (no event).
3. **Logging reliance:** Real-time detection of pause/unpause depends on off-chain server logs (e.g., Socket.IO handlers in `server/socket-io/main.js`) or periodic polling of the config account.

## Assessment

- **Not a vulnerability** (no leak, no drainage, no griefing via pause itself).
- **Operational gap** (event-tracking inconsistency; pause state changes are invisible to event-based monitoring).
- **Severity: LOW** — a minor UX inconvenience, not a security bug.

## Recommendation

Emit `Paused` and `Unpaused` events in both `pause_program` and `unpause_program` for consistency with `ConfigUpdated`.

Example fix (v1 or v2):
```rust
#[event]
pub struct Paused {
    pub timestamp: i64,
}

#[event]
pub struct Unpaused {
    pub timestamp: i64,
}

pub fn pause_program(ctx: Context<PauseProgram>) -> Result<()> {
    ctx.accounts.config.is_paused = true;
    emit!(Paused {
        timestamp: Clock::get()?.unix_timestamp,
    });
    Ok(())
}
```
