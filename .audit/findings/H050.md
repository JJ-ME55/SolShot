## Executive Summary

This recheck evaluates whether the two combined attack chains (S001 = H001+H002+H005 and
S002 = H003+H007) are still viable after code changes introduced in the current audit cycle.

S001 remains a CRITICAL-severity chain on v1 (all three legs fully active). On v2 it is
PARTIALLY OPEN: H001 and H005 are still effective, H002 is mitigated for in-flight matches
(per-match snapshot atomic at create_match) but remains open for all new matches created
post-compromise. S002 is PARTIALLY OPEN on v1 (H007 leg active; H003 leg closed by the
distinctness re-validation at v1:96-98). S002 is fully CLOSED on v2 (H003 fixed at v2:125-127
AND H007 fixed by removal of pause guard from CancelMatch at v2:757-761).

**Net assessment:** An authority key compromise on v1 is a complete protocol kill (S001 full
chain). On v2 the same compromise is contained for in-flight fees but still delivers winner
fraud (H005) against all matches, fee theft on all NEW matches, and permanent governance
lockout (H001). The 48-hour griefing path (S002) is fully closed on v2 only.

## Hypothesis Investigated

**S001:** H001 (one-step authority transfer) + H002 (fee destination hijack at settle) +
H005 (authority winner selection fraud). A single authority key compromise enables:
(a) redirect treasury/ops to attacker wallets, (b) settle all active matches with a
controlled player as winner, (c) rotate authority to lock out recovery.

**S002:** H003 (distinctness poison — set treasury == ops to break settlement) +
H007 (pause guard on cancel_match creates 48h lockup when combined with H003).
A compromised authority atomically poisons the config and pauses to trap all in-flight
deposits for up to 48 hours.

## Chain Status

### S001 on v1: STILL OPEN (full chain)

All three legs are active:
- **TX0 (H002):** `update_config(new_treasury=attacker_A, new_ops=attacker_B)` — instant effect,
  no timelock. v1 settle reads LIVE config (`v1:686`), so all subsequent settlements redirect
  10% fees to attacker addresses.
- **TX1-N (H005):** `settle_match(winner=attacker_player)` — authority freely picks from
  `escrow.players[]` (`v1:676-679`). Attacker registers a controlled wallet as player via
  authority-only `create_match`. 90% per pot flows to attacker. Combined with TX0, 100%
  extraction per new match.
- **TX_final (H001):** `update_config(new_authority=attacker_key2)` — one-step rotation at
  `v1:80-83`. Permanent governance lockout. No `pending_authority` field exists.

**Pre-existing in-flight matches** that have no attacker-registered player yield only 10% fee
theft (TX0 still applies). New matches created post-compromise yield 100% extraction.

**Optional:** After TX_final, authority can `pause_program` (v1 H007 still open) → traps
remaining Active matches for up to 1200s until `permissionless_reclaim` deadline.

---

### S001 on v2: PARTIALLY OPEN

- **H001 (TX_final):** STILL OPEN — same one-step rotation as v1.
- **H002 (TX0, in-flight):** MITIGATED — `settle_match` reads `escrow.treasury_snapshot`
  (`v2:717, 726`) frozen at `create_match`. A mid-match config rotation does NOT redirect
  fees for already-created matches.
- **H002 (TX0, new matches):** STILL OPEN — snapshot is populated from CURRENT config at
  create_match time (`v2:211-214`). Any match created AFTER TX0 inherits the poisoned
  treasury/ops. Attacker can create new matches with self as player and attacker addresses
  as snapshot values.
- **H005:** STILL OPEN — authority winner selection is unconstrained between registered
  players in both versions. V2 amplifies impact (10-player pots up to 1000 SOL vs 400 SOL
  in v1).

**Effective blast on v2 after compromise:**
1. In-flight matches: H005 still works (90% winner extraction per match where attacker
   controls a registered player); fees are snapshot-protected but winner is not.
2. New matches: Full 100% extraction (H005 winner + H002 fee redirect on new-match
   snapshots).
3. Permanent governance lockout via H001.

### S002 on v1: PARTIALLY OPEN (H007 leg only)

- **H003 leg: CLOSED.** `update_config` at `v1:94-98` now re-validates distinctness
  post-update. Setting `treasury == ops` is rejected with `DuplicateFeeAccount`. TX0 of
  the original S002 PoC cannot succeed.
- **H007 leg: STILL OPEN.** `pause_program` sets `is_paused = true`. `CancelMatch` struct
  in v1 still enforces `constraint = !config.is_paused @ ProgramPaused` at `v1:729`.
  Players cannot self-cancel a paused match. Combined with H001 (authority rotates to
  dead key → no unpause possible), this delivers a 1200s (20-minute) lockup until
  `permissionless_reclaim` fires.

**Chain is weakened but not dead:** Without the H003 poison leg, the attacker can only
pause (blocking cancel, not settle). Settlement is still available to the authority while
paused on v1 (verify: v1 SettleMatch config account at `v1:699-706` does have
`constraint = !config.is_paused`). Wait — if pause also blocks settle on v1, then the
authority cannot settle while paused, which actually reduces attacker's options. The 20-min
lockup is the primary remaining impact on v1 from S002 with H003 fixed.

---

### S002 on v2: CLOSED

- **H003 leg: CLOSED** at `v2:125-127` — same fix as v1.
- **H007 leg: CLOSED** — `CancelMatch` in v2 has no pause guard (`v2:757-761`). Players
  can always cancel after timeout regardless of pause state. `permissionless_reclaim` also
  has no config account in either version so it is pause-immune by construction.

Both legs of S002 are independently closed on v2. The chain is dead.

## Recommended Fixes (Priority Order)

1. **Add `pending_authority` field to `GlobalConfig` (closes H001, both versions):**
   Two-step propose/accept pattern. Eliminates governance lockout from single key compromise.
   This is the single highest-impact fix across all chains.

2. **Add timelock to treasury/ops rotation in v1 `update_config` (closes H002 v1 gap):**
   Pending treasury/ops values that activate after a 24h delay prevent instant fee redirect.
   v2's snapshot architecture already mitigates in-flight; v1 needs a timelock or snapshot.

3. **Remove pause guard from v1 `CancelMatch` (closes H007 v1, eliminates S002 v1 residual):**
   Mirrors the fix already present in v2 at `v2:757-761`. Low-risk one-line change to
   `v1:726-731` account struct.

4. **Migrate to multisig for `config.authority` before mainnet (closes S001 precondition):**
   Per TODO at `v1:1` (OC-13). Raises key compromise difficulty from 1-of-1 to M-of-N.
