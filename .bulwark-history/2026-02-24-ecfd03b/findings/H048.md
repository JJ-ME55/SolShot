## Verdict: PARTIALLY CONFIRMED — CSP EXISTS BUT IS INCOMPLETE AND MISDELIVERED

**Severity: MEDIUM** (downgraded from the HIGH originally attributed to H-13 / W7)

The hypothesis as stated — "Vercel-deployed client has no Content Security Policy" — is **partially refuted** by a CSP meta tag present in `client/public/index.html`. A CSP has been added since H032 was written. However, the implementation has three concrete deficiencies that preserve meaningful residual risk:

1. The CSP is delivered via HTML `<meta>` tag, not an HTTP response header. This is a weaker delivery mechanism with documented browser limitations.
2. The CSP meta tag allows a `<script>` in `index.html` that loads `telegram-web-app.js` from the same origin — that script is self-hosted, so `script-src 'self'` technically covers it. However, the `connect-src` directive includes `ws://localhost:5001` (unencrypted WebSocket) in what will become the production HTML, a configuration hygiene issue inherited from the server's own CSP (identified in W10).
3. The four non-CSP security headers identified in H032/W7 — `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, and `Permissions-Policy` — are **still absent** from `client/vercel.json`. These cannot be provided by a meta tag; they require HTTP response headers.

The clickjacking risk (no `X-Frame-Options`) identified as an active, present-day attack vector in H032 remains fully unmitigated.

### 2. index.html — CSP Meta Tag Is Present

**File:** `C:/Users/johnk/SolShot-clean/client/public/index.html` (line 7)

```html
<meta http-equiv="Content-Security-Policy" content="default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com; img-src 'self' data: blob:; connect-src 'self' https://api.devnet.solana.com wss://api.devnet.solana.com https://api.mainnet-beta.solana.com wss://api.mainnet-beta.solana.com https://solshot-server.onrender.com wss://solshot-server.onrender.com ws://localhost:5001 wss://localhost:5001; frame-src 'none'; object-src 'none'; base-uri 'self';" />
```

A CSP is present and covers the primary directives: `script-src 'self'` blocks injected external scripts, `frame-src 'none'` denies embedding at the CSP level, and `object-src 'none'` prevents plugin exploitation. This represents meaningful partial remediation of the original H-13 / W7 finding.

---

### 3. Deficiency A — Meta Tag vs. HTTP Header Delivery

A CSP delivered via `<meta http-equiv="Content-Security-Policy">` has documented browser limitations compared to delivery via an HTTP `Content-Security-Policy` response header:

- **`report-uri` / `report-to` directives are ignored** when set via meta tag (per CSP Level 3 specification). Any future violation reporting mechanism cannot be added to the meta-tag CSP.
- **The meta tag is parsed after the HTML parser begins processing the document.** Any inline scripts or resources referenced before line 7 of the document would execute before the meta-tag CSP is applied. In the current `index.html`, the `<meta>` is on line 7 and there are no earlier `<script>` tags, so this is not currently exploitable. However, it is a structural fragility: any script added above line 7 (e.g., a tag manager or third-party loader) would execute outside CSP coverage.
- **The `<script>` tag on line 8** (`<script src="%PUBLIC_URL%/js/telegram-web-app.js"></script>`) loads an external script immediately after the meta tag. Because this script is served from the same origin (`%PUBLIC_URL%`), `script-src 'self'` covers it. The file `client/public/js/telegram-web-app.js` exists and is self-hosted, so this is not a policy violation. However, if `telegram-web-app.js` were ever swapped for a CDN-hosted version, this script tag would immediately violate the CSP and break Telegram integration — the risk is a fragile dependency between the CSP policy and the script hosting decision.
- **HTTP header CSP takes precedence over meta-tag CSP** when both are present. Since `vercel.json` sets no `Content-Security-Policy` header, the meta-tag CSP is the sole enforcing mechanism. This is functional but the intent to have Vercel enforce headers at the CDN edge layer (before HTML is returned) is not achieved.

---

### 4. Deficiency B — ws://localhost:5001 in connect-src

The meta-tag CSP `connect-src` includes:

```
ws://localhost:5001 wss://localhost:5001
```

This is an unencrypted WebSocket development endpoint in a policy that will be served to production users. A browser receiving this page on `solshot.gg` would be told by the CSP that connecting to `ws://localhost:5001` is permitted. While this does not enable any attack (no cross-origin page can force the browser to connect to a victim's localhost), it leaks internal development topology to any user who reads response headers or the page source. This same issue was identified as W10 in context/07-web-02-cors-headers.md on the server's CSP.

---

### 5. Deficiency C — X-Frame-Options Absent (Clickjacking Active)

Neither `vercel.json` (HTTP header) nor `index.html` (meta tag) sets `X-Frame-Options`. The CSP `frame-src 'none'` directive controls which origins the **current page** can embed as frames — it does not prevent the current page from being embedded as a frame in a third-party document. Frame-embedding restrictions require either `X-Frame-Options` (HTTP header only — meta tag is ignored by browsers) or the CSP `frame-ancestors` directive.

The meta-tag CSP does not include `frame-ancestors`. The `frame-src 'none'` directive in the meta-tag CSP is semantically unrelated to this protection: it restricts what this page embeds, not who can embed this page.

**Current state:** Any external page can embed `solshot.gg` in an `<iframe>`. The wallet connect modal, wager deposit confirmation, and SHOT burn approval UI are all frameable today. H032 Scenario C (clickjacking of wallet approval dialogs) is fully unmitigated.

---

### 6. Server Helmet CSP Confirmation — Does Not Apply to Client

The server's `helmet()` CSP (in `server/index.js:70-95`) is applied only to Express API responses (`/`, `/health`, `/stats`, `/api/auth/verify`). The Vercel-served client HTML and JavaScript bundles are served by Vercel's CDN, not by the Express server. The server CSP does not and cannot govern any Vercel-served response. This architectural separation was confirmed in context/07-web-02-cors-headers.md (W7) and remains accurate.

## Summary of Residual Risk

| Issue | Status | Impact |
|-------|--------|--------|
| No CSP at all on client | REMEDIATED (partial) | CSP meta tag present with correct `script-src 'self'` |
| CSP delivered via meta tag, not HTTP header | OPEN | `report-uri` disabled; fragile parse-order dependency; not CDN-edge enforced |
| `ws://localhost:5001` in connect-src | OPEN | Dev endpoint leaked in production CSP; cosmetic but indicates copy-paste from server config |
| `X-Frame-Options` absent | OPEN | Clickjacking of wallet approval dialogs unrestricted; active today, no XSS required |
| `X-Content-Type-Options` absent | OPEN | MIME sniffing protection not enforced |
| `Referrer-Policy` absent | OPEN | Referrer header sent on navigation to third-party links |
| `Permissions-Policy` absent | OPEN | Camera, microphone, geolocation permissions not explicitly denied |
| `frame-ancestors` absent from CSP | OPEN | Equivalent to `X-Frame-Options DENY` in modern CSP; absent here |

The highest-priority residual risk is the absent `X-Frame-Options` / `frame-ancestors`. The H032 clickjacking scenario requires no XSS precondition and is active against any version of the deployed client that lacks this header.

## Recommendations

All five recommendations from H032-R1 remain applicable. They are restated here with updated priority accounting for the partial remediation.

### R1 — Move CSP from meta tag to vercel.json header and add missing headers (HIGH PRIORITY — Before Mainnet)

Replace the current `client/vercel.json` headers configuration with:

```json
{
  "headers": [
    {
      "source": "/(.*)",
      "headers": [
        { "key": "X-Frame-Options", "value": "DENY" },
        { "key": "X-Content-Type-Options", "value": "nosniff" },
        { "key": "Referrer-Policy", "value": "strict-origin-when-cross-origin" },
        { "key": "Permissions-Policy", "value": "camera=(), microphone=(), geolocation=()" },
        {
          "key": "Content-Security-Policy",
          "value": "default-src 'self'; script-src 'self'; connect-src 'self' https://api.devnet.solana.com wss://api.devnet.solana.com https://api.mainnet-beta.solana.com wss://api.mainnet-beta.solana.com https://solshot-server.onrender.com wss://solshot-server.onrender.com; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com; img-src 'self' data: blob:; frame-src 'none'; frame-ancestors 'none'; object-src 'none'; base-uri 'self';"
        }
      ]
    },
    {
      "source": "/static/(.*)",
      "headers": [
        { "key": "Cache-Control", "value": "public, max-age=31536000, immutable" }
      ]
    }
  ]
}
```

Key changes from the current meta tag:
- Removes `ws://localhost:5001` and `wss://localhost:5001` from `connect-src`
- Adds `frame-ancestors 'none'` (the modern, CSP-level equivalent of `X-Frame-Options: DENY`)
- Delivers CSP as an HTTP header (CDN-edge enforced, enables future `report-to` integration)
- `X-Frame-Options: DENY` is added alongside `frame-ancestors 'none'` for compatibility with older browsers that do not support CSP Level 2

### R2 — Remove CSP meta tag from index.html after R1 is deployed

Once the HTTP header CSP is live via `vercel.json`, the `<meta http-equiv="Content-Security-Policy">` tag in `index.html` should be removed. An HTTP header CSP takes precedence over a meta-tag CSP when both are present, but keeping both creates maintenance burden (two places to update) and potential policy confusion. The meta tag should be removed after confirming the header CSP is working correctly in Vercel's preview environment.

### R3 — Remove ws://localhost:5001 from connect-src in index.html (Immediate)

This fix can be deployed independently of R1/R2 at any time and requires no coordination:

In `client/public/index.html`, remove `ws://localhost:5001 wss://localhost:5001` from the `connect-src` value in the meta-tag CSP. The game server connects via `wss://` in production; the `ws://` entry is only needed in local development where the CSP meta tag is already less relevant (CRA dev server has its own headers). If local development requires this, gate it with a conditional in `config-overrides.js` or inject it only when `NODE_ENV=development`.
