# H049 — styleSrc unsafe-inline in Server CSP

**Audit:** Dinh's Bulwark — Off-Chain Security
**Hypothesis ID:** H049
**Date:** 2026-02-23
**Investigator:** Hypothesis Investigator (Phase 3)
**Status:** CONFIRMED (with scope correction)
**Verdict:** LOW — `'unsafe-inline'` is present on `styleSrc` in the server's helmet CSP. `scriptSrc` is correctly locked to `'self'` with no `'unsafe-inline'`. However, the server CSP is applied to an Express API server that serves only JSON and one plain-text string; it does not serve the React/Phaser client HTML. The `'unsafe-inline'` style directive is therefore decorative on this server and carries no practical CSS injection risk for the server itself. The genuine and significantly more severe gap is the companion finding: the client deployment on Vercel sets **no CSP at all** (W7 in context/07-web-02-cors-headers.md, ARCHITECTURE.md H-13). That is where wallet interactions, wager UI, and SHOT burns are rendered; it is the correct threat surface and is already tracked as a separate HIGH finding.

---

## 1. Summary

The hypothesis that `server/index.js` uses `'unsafe-inline'` on `styleSrc` is **correct**. The helmet CSP at line 75 reads:

```javascript
styleSrc: ["'self'", "'unsafe-inline'"],
```

The hypothesis that this represents a meaningful XSS vector for the server is **not confirmed at the asserted severity**. The CSP in question is set on the Express API server, which serves:

- `GET /` — plain text: `"SolShot server running"` (not HTML)
- `GET /health` — JSON
- `GET /stats` — JSON (admin-gated)
- `POST /api/admin/reload-keys` — JSON (admin-gated)

None of these responses render user-controlled content as CSS. The server does not serve the game client. The CSP header is sent on these API responses but it has no practical protective role because none of the responses are HTML documents that a browser would parse with CSS.

`scriptSrc` is correctly set to `["'self'"]` with no `'unsafe-inline'` and no `'unsafe-eval'`. The server-side script execution attack surface (which would be most dangerous) is not weakened.

The actual at-risk surface — the React/Phaser client hosted on Vercel — has **zero** CSP headers, making the server's `'unsafe-inline'` style directive comparatively irrelevant.

## 2. Vulnerability Detail

### 2.1 Server CSP configuration

**File:** `server/index.js`
**Lines:** 70–95

```javascript
// CS-03: Enable Content Security Policy (DB: H031)
app.use(helmet({
    contentSecurityPolicy: {
        directives: {
            defaultSrc: ["'self'"],
            scriptSrc: ["'self'"],                         // CORRECT — no unsafe-inline
            styleSrc: ["'self'", "'unsafe-inline'"],       // H049 subject — unsafe-inline present
            imgSrc: ["'self'", "data:", "blob:"],
            connectSrc: [
                "'self'",
                "https://api.devnet.solana.com",
                "wss://api.devnet.solana.com",
                "https://api.mainnet-beta.solana.com",
                "wss://api.mainnet-beta.solana.com",
                "https://solshot-server.onrender.com",
                "wss://solshot-server.onrender.com",
                "ws://localhost:5001",
                "wss://localhost:5001",
            ],
            fontSrc: ["'self'", "https://fonts.gstatic.com"],
            frameSrc: ["'none'"],
            objectSrc: ["'none'"],
            baseUri: ["'self'"],
        },
    },
    crossOriginEmbedderPolicy: false,
}))
```

The `'unsafe-inline'` value on `styleSrc` permits inline `<style>` tags and `style="..."` attributes in any HTML document served by this server. On a pure JSON API server, no such HTML documents exist.

### 2.2 What CSS-only injection can and cannot do

Granting `'unsafe-inline'` on `styleSrc` alone (with `scriptSrc` locked to `'self'`) does enable a class of attacks in browsers when applied to a real HTML-rendering endpoint:

| Technique | Requires unsafe-inline style? | Requires unsafe-inline script? | Viable here? |
|-----------|------------------------------|---------------------------------|--------------|
| CSS exfiltration (attribute selectors + background-image) | Yes | No | No — no HTML served |
| CSS keylogger (input[value] selectors) | Yes | No | No — no HTML with inputs |
| DOM-based CSS injection via injected `<style>` | Yes | No | No — no HTML served |
| Content spoofing via CSS overlay | Yes | No | No — no HTML served |
| Full JS execution (XSS) | No | Yes (unsafe-inline or eval) | Not enabled — scriptSrc is `'self'` only |

In a hypothetical future where the server began serving HTML responses with user-controlled content, the `'unsafe-inline'` style setting would become exploitable for CSS-based data exfiltration attacks. At present that path does not exist.

### 2.3 The companion gap: client has no CSP at all

**File:** `client/vercel.json`

```json
{
  "framework": "create-react-app",
  "buildCommand": "npm run build",
  "outputDirectory": "build",
  "rewrites": [
    { "source": "/(.*)", "destination": "/index.html" }
  ],
  "headers": [
    {
      "source": "/static/(.*)",
      "headers": [
        { "key": "Cache-Control", "value": "public, max-age=31536000, immutable" }
      ]
    }
  ]
}
```

The client deployment on Vercel sets no `Content-Security-Policy`, no `X-Frame-Options`, no `X-Content-Type-Options`, no `Referrer-Policy`, and no `Permissions-Policy` headers on any route. The client is the HTML-rendering surface where:

- Solana wallet adapter connects and signs transactions
- Wager amounts are displayed and accepted
- SHOT burn transactions are constructed and signed
- `window.socket` and `window.solWallet` are exposed as globals

Any XSS in the React or Phaser layer on this deployment runs with zero browser-enforced containment. This is the correct threat surface for CSS injection and XSS and is tracked as a HIGH finding (H-13 in ARCHITECTURE.md, W7 in context/07-web-02-cors-headers.md).

## 3. Severity Assessment

**Severity: LOW**

| Factor | Assessment |
|--------|------------|
| Is `'unsafe-inline'` present on `styleSrc`? | Yes — confirmed at `server/index.js:75` |
| Does `scriptSrc` also contain `'unsafe-inline'`? | No — `scriptSrc: ["'self'"]` only |
| Does the server serve HTML that renders user-controlled content? | No — the four endpoints serve plain text and JSON only |
| Is CSS injection practical on the current server routes? | No — no HTML document rendering surface |
| Would removal reduce attack surface? | Marginally yes — eliminates the directive if the server ever starts serving HTML |
| Is the wallet/wager/burn UI protected by any CSP? | No — a separate more severe gap (HIGH) |

The hypothesis is confirmed as true in isolation (the directive exists) but the asserted severity does not match the actual deployment context. The real risk — the client having no CSP — is an independently tracked finding of significantly higher severity.

## 5. Scope Clarification: Server CSP vs. Client CSP

The CSP applied by helmet on the Express server and the CSP (absent) on the Vercel client are two entirely separate surfaces:

```
Express server (Render)              Vercel client
=====================                ===============
Routes: /  /health /stats            Routes: / (all — SPA)
        /api/admin/reload-keys
Response type: plain text, JSON      Response type: HTML + JS bundles
helmet CSP: SET                      Vercel CSP: NOT SET
styleSrc: unsafe-inline (present)    No CSP at all
scriptSrc: 'self' only (correct)     (no browser protection)

^ This finding (LOW)                 ^ H-13 / W7 (HIGH)
  Decorative unsafe-inline             Wallet adapter, wager UI,
  on a JSON-only server                SHOT burns — no containment
```

The hypothesis investigation confirms the `'unsafe-inline'` directive exists as stated. The correct follow-up action is to address both: clean up the server's decorative `'unsafe-inline'` as a minor hygiene fix, and separately implement a full CSP on the Vercel client deployment as the substantive security control.

## 6. Recommendations

### R1 — Remove `'unsafe-inline'` from server `styleSrc` (Minor hygiene)

The server does not serve HTML that requires inline styles. Remove the directive so the CSP accurately reflects the server's actual needs and eliminates the directive as a future footgun if HTML serving is ever added:

```javascript
// server/index.js — line 75
// Before:
styleSrc: ["'self'", "'unsafe-inline'"],

// After:
styleSrc: ["'self'"],
```

This is a one-line change with zero functional impact on current behavior.

### R2 — Add a full CSP to the Vercel client deployment (Primary fix — tracked separately as H-13 / W7)

Add security headers to `client/vercel.json` covering all routes. This is the fix that actually matters for XSS containment:

```json
{
  "source": "/(.*)",
  "headers": [
    { "key": "X-Frame-Options", "value": "DENY" },
    { "key": "X-Content-Type-Options", "value": "nosniff" },
    { "key": "Referrer-Policy", "value": "strict-origin-when-cross-origin" },
    { "key": "Permissions-Policy", "value": "camera=(), microphone=(), geolocation=()" },
    {
      "key": "Content-Security-Policy",
      "value": "default-src 'self'; script-src 'self'; connect-src 'self' https://api.devnet.solana.com wss://api.devnet.solana.com https://solshot-server.onrender.com wss://solshot-server.onrender.com; img-src 'self' data: blob:; style-src 'self' 'unsafe-inline'; font-src 'self' https://fonts.gstatic.com; frame-src 'none'; object-src 'none';"
    }
  ]
}
```

Note: `'unsafe-inline'` on `style-src` in the **client** CSP may be genuinely necessary to support Phaser.js canvas styling and React's inline style system. Unlike on the server, on the client this is an informed trade-off. `'unsafe-eval'` should not be added. This recommendation is the substance of the higher-severity H-13 / W7 finding and is out of scope for the present H049 investigation.

### R3 — Remove `ws://localhost:5001` from the server CSP `connectSrc` (Hygiene)

The unencrypted `ws://` entry at `server/index.js:85` is a development artifact in what is intended to be the production server CSP. Gate it behind `NODE_ENV !== 'production'` or remove it:

```javascript
// Conditional inclusion for development only
...(process.env.NODE_ENV !== 'production' ? ["ws://localhost:5001", "wss://localhost:5001"] : []),
```

---

## 7. Verdict

**CONFIRMED LOW.**

The `'unsafe-inline'` directive on `styleSrc` exists at `server/index.js:75` as stated in the hypothesis. `scriptSrc` is correctly hardened to `'self'` only — there is no `'unsafe-inline'` on the script execution surface. The CSP applies to an Express API server that serves only JSON and one plain-text string; no HTML document rendering surface exists on this server, so the `'unsafe-inline'` style directive has no practical attack surface to enable. It should be removed as a hygiene fix to prevent it becoming a footgun. The materially important companion gap — the Vercel-hosted game client serving the wallet/wager UI with no CSP whatsoever — is already catalogued as a HIGH finding (H-13 / W7) and requires the remediation described in R2.
