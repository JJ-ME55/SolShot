## H084 — shopReady Race Condition Duplicate

**Verdict:** CONFIRMED DUPLICATE

**Severity:** INFO

**Evidence:**
Strategy H084 maps to Architecture.md section 7.2, "Shared Vulnerability Patterns" note on `shopReady`. This is **same finding as H056** from initial audit:

shopReady state (main.js line 39) is checked at `ready` event (line 1561) without atomic serialization. Concurrent shop completions + ready events can race: both players mark ready before both finish shopping, or one player sees stale shopReady state.

**Overlap:** H056 already documented this race. H084 is confirmation of duplicate, not new finding.

**Impact:** Both players can move to match start with incomplete shop state. Lower severity than concurrent burns or settlement races (cosmetic weapon state, not financial).

**Recommendation:** See H056 analysis. Merge H056 + H084. Use `withLock()` on ready event to serialize shop completion verification.
