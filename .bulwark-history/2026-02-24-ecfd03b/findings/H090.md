## H090 — Express Rate Limit Config Review

**Verdict:** CONFIRMED

**Severity:** MEDIUM

**Evidence:**
- server/index.js:100-107 — httpLimiter: 100 req/15min per IP, applies to all HTTP endpoints
- Line 44-67 — Socket.IO per-IP connection limit (MAX_CONNECTIONS_PER_IP = 100) at handshake only
- server/socket-io/main.js:1213-1280 — joinQueue handler: NO per-event rate limiting after socket connects
- No maxHttpBufferSize set in Socket.IO config (architecture.md line 93: "not configured")

**Analysis:**
HTTP endpoints are rate-limited (100 req/15min) but:
1. joinQueue event (wagered match entry) has NO rate limiting once socket is connected
2. Socket.IO handshake connection-limit does not apply to event frequency after connection
3. Attacker can: connect once (passes handshake limit), then send 1000 joinQueue events in 1 second with zero delay
4. maxHttpBufferSize missing — no protection against oversized payloads (DoS on WebSocket upgrade buffer)

**Recommendation:** Add per-socket event rate limiting (e.g., 10 joinQueue events/60s per socket) and set maxHttpBufferSize ≤ 100KB in Socket.IO config.
