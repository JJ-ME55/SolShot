## H092 — Database Index Missing for Burn Lookups

**Verdict:** NOT VULNERABLE

**Severity:** INFO

**Evidence:**
- server/socket-io/main.js:41-42 — verifiedBurnTxs is in-memory Set: `const verifiedBurnTxs = new Set()`
- server/services/shot-token.js:42 — same in-memory Set (module-level state)
- server/socket-io/main.js:1611-1640 — prestigeBurn handler checks `verifiedBurnTxs.has(txSignature)` before verification
- Database persistence: ServerState model exists but burn tracking is in-memory, no DB writes
- Architecture.md line 69: "verifiedBurnTxs Set is in-memory only (lost on restart)"

**Analysis:**
The design is intentional: burn verification uses in-memory Set for O(1) replay detection. Database is NOT queried for burn verification. No index needed because:
1. Lookups are in-memory only (no DB query)
2. Lost on restart (acceptable for devnet; would need persistence for mainnet)
3. Scalability: Set handles millions of entries efficiently

**Vulnerability:** None. This is a design choice with known tradeoff: fast replay detection vs. loss on restart.

**Recommendation:** Document this as a known limitation for mainnet. If production deployment needed, migrate to persistent burn registry (e.g., verified_burns table with txSignature index).
