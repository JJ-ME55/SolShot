## H095 — Memory State Divergence After Restart

**Verdict:** CONFIRMED

**Severity:** HIGH

**Evidence:**
- server/socket-io/main.js:22-79 — All state stored in-memory Maps/Objects: rooms, matchStates, goldStates, weaponInventories, wagerStates, authenticatedWallets, pendingReconnects, turnTimers, depositTimers, failedSettlements
- Architecture.md lines 59-71 — Complete state ephemeral; lost on restart; only escrow PDA acts as persistence
- server/socket-io/main.js:77-120 — failedSettlements has 5 retry attempts then abandoned; in-memory only
- If server crashes during settlement: wagers, deposits, match results all lost in-memory; on-chain escrow state unchanged

**Analysis:**
Failure modes:
1. **Crash during settlement:** winner=null, match result lost in DB, escrow PDA remains in SETTLED state on-chain with no record of settlement in app
2. **Crash during rematch:** playAgainRequest creates no new escrow, wagerStates preserved in-memory, settlement attempts fail → winner denied payout
3. **Crash during reconnect window (30s):** pendingReconnects cleared, player permanently locked out of match until 24h on-chain timeout expires
4. **Crash during deposit timeout:** depositTimers cleared, escrow never cancels, wagers locked for 24h

**Recommendation:**
1. Persist critical state to MongoDB: active matches, pending deposits, failed settlements
2. Implement state recovery on startup: read from DB, resume pending operations
3. Reduce reconnect window from 30s to 10s (shorter window = less impact on restart)
