## H118 — Server Restart Creates Orphaned Escrows

**Verdict:** CONFIRMED

**Severity:** HIGH

**Evidence:**
All match state is in-memory (server/socket-io/main.js:22-79): `rooms`, `wagerStates`, `playerGold`, `turnTimers`, `depositTimers`, `failedSettlements`, `verifiedBurnTxs`. On restart:

1. All Maps/Objects cleared
2. Escrow PDAs remain on-chain (created in previous instance)
3. Match in `AwaitingDeposits` state becomes orphaned
4. 24h timeout (IDL:6018 SettlementExpired) is the only backstop

An attacker creates high-value match, crashes server (or waits for crash), and the escrow idles for 24h. Neither player can reclaim; funds locked.

**Recommendation:** Persist critical match state to MongoDB: `{ roomId, p1, p2, wagerSOL, escrowPDA, createdAt, state }`. On startup, scan DB for active escrows and re-initialize `wagerStates`/`depositTimers`.

---

**Notes:** `failedSettlements` is in-memory retry queue (main.js:82-103) with 5 retries then discard. Lost on restart. Permissionless 48h reclaim (IDL:364-423) is backstop but not player-friendly.
