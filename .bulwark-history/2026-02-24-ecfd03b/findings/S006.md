## What the Inspector Chain Would Enable (Hypothetical)

If `--inspect=0.0.0.0:9229` were added to any start script (a common developer mistake that reaches production), any network-accessible client could connect to the Chrome DevTools Protocol endpoint and:

1. Execute `Runtime.evaluate({ expression: "require('v8').writeHeapSnapshot()" })` to trigger a heap snapshot.
2. Search the resulting `.heapsnapshot` file for `Array` objects containing 64 integers in the range 0–255 — the signature of a Solana keypair JSON array.
3. Recover the full 64-byte escrow authority secret key from H014's confirmed heap exposure (the unzeroed `secretKeyArray`).
4. Alternatively: evaluate `process.env.SOLANA_KEYPAIR_JSON` directly via the inspector's `Runtime.evaluate` RPC — the full JSON string remains in `process.env` for the entire process lifetime per H015.

This would give the attacker the escrow authority keypair, enabling them to:
- Call `settle_match` with any `winner_account` they control, draining all active escrow PDAs.
- Call `cancel_match` to refund all active matches (griefing).
- Redirect treasury and ops fee payments to attacker-controlled accounts.

The on-chain Anchor program's `has_one = authority` constraint would not protect against this because the attacker has the authority private key.

## Constituent Finding Analysis

### H014 — Incomplete Heap Zeroing (MEDIUM, CONFIRMED)

**File:** `server/services/keys.js`, lines 41–63

```js
secretKeyArray = JSON.parse(keypairJson);   // line 45 — plain Array<number>, never zeroed
const bytes = Uint8Array.from(secretKeyArray);  // line 51
_escrowKeypair = Keypair.fromSecretKey(bytes);  // line 52
bytes.fill(0);   // line 55 — only bytes zeroed; secretKeyArray remains live in V8 heap
```

The `secretKeyArray` — a plain JavaScript `Array` of 64 numbers containing the raw secret key bytes — is never zeroed. It remains in the V8 heap from the time `JSON.parse()` returns until the GC collects it. Because `initKeys()` is called once at startup and the old-object heap in V8's generational GC has long collection intervals, the array may persist for the entire process lifetime.

Any mechanism that produces a V8 heap snapshot (inspector, `v8.writeHeapSnapshot()`, `process.report.writeReport()`, OS core dump on crash, Render crash report) exposes this array.

### H015 — SOLANA_KEYPAIR_JSON Persistent in process.env (HIGH, POTENTIAL)

**File:** `server/services/keys.js`, lines 33 and 45

```js
const keypairJson = process.env.SOLANA_KEYPAIR_JSON;  // line 33 — read but never deleted
if (keypairJson) {
    secretKeyArray = JSON.parse(keypairJson);  // line 45
}
// No: delete process.env.SOLANA_KEYPAIR_JSON anywhere in codebase
```

`process.env.SOLANA_KEYPAIR_JSON` contains the full 64-byte keypair as a JSON string and persists in `process.env` for the process lifetime. Any future APM SDK addition (Sentry, Datadog, New Relic) that captures `process.env` on exception — which many do by default — would exfiltrate the private key.

More immediately: if any developer adds `console.log(process.env)` during a production incident (a common debugging action), the key appears in Render's log drain in plaintext.

The two constituent vulnerabilities together create multiple extraction paths that do not require the inspector:

## Recommendations

### For the Inspector-Specific Chain (Preventive)

Even though no inspector flag exists today, add a production startup assertion to prevent accidental inspector enablement:

```js
// server/index.js — at startup
if (process.execArgv.some(arg => arg.startsWith('--inspect'))) {
    console.error('[FATAL] Node.js inspector is enabled — refusing to start in production mode');
    process.exit(1);
}
```

This provides a safety net if a developer accidentally adds `--inspect` to a production script.

Document in the deployment runbook: "Never add `--inspect` or `NODE_OPTIONS=--inspect` to production scripts or environment variables. If debugging is needed, use ephemeral non-production instances."

### For H014 — Zero the Source Array

```js
// server/services/keys.js, after line 51 (Uint8Array.from)
const bytes = Uint8Array.from(secretKeyArray);
// Zero source array before proceeding
for (let i = 0; i < secretKeyArray.length; i++) secretKeyArray[i] = 0;
_escrowKeypair = Keypair.fromSecretKey(bytes);
bytes.fill(0);
```

### For H015 — Delete env var Immediately After Use

```js
// server/services/keys.js, inside initKeys()
if (keypairJson) {
    secretKeyArray = JSON.parse(keypairJson);
    delete process.env.SOLANA_KEYPAIR_JSON;   // add this immediately after parsing
}
```

### Combined Recommendation: Prefer File-Based Loading with Immediate Zeroing

Load the keypair from a file path (`SOLANA_KEYPAIR_PATH`) rather than from a JSON env var. The file system is not captured by most APM SDKs. Read the file, parse, zero the buffer, delete the reference — this is strictly safer than an env var that lingers.
