# H007 — refundWager Wrong Parameters Silent Failure
**Status:** CONFIRMED
**Severity:** HIGH
**Confidence:** HIGH
**Origin:** KB

## Summary

`refundWager()` is called with only 2 arguments at the sole call site in `main.js`. The function signature requires 5 arguments (`playerAddress`, `wagerSOL`, `matchId`, `playerOneAddress`, `playerTwoAddress`) to trigger an on-chain `cancel_match`. The missing 3 arguments evaluate to `undefined`, causing the internal guard condition to be falsy, the on-chain cancellation to be silently skipped, and the function to fall through to an off-chain logging stub. In a LOBBY-phase disconnect where one or both players have already deposited, their funds remain locked in the escrow PDA with no on-chain refund issued.

## Evidence

**Function signature — `server/services/solana.js` lines 235–253:**
```js
export async function refundWager(playerAddress, wagerSOL, matchId, playerOneAddress, playerTwoAddress) {
    if (wagerSOL === 0) {
        return { success: true, txSignature: null };
    }

    // If escrow is live, cancel on-chain (refunds all deposited players)
    if (isEscrowEnabled() && matchId && playerOneAddress && playerTwoAddress) {  // line 241
        const result = await cancelMatchEscrow(matchId, playerOneAddress, playerTwoAddress);
        ...
    }

    // Fallback: log refund
    logger.info({ amount: wagerSOL }, '[Solana] Refund (off-chain)');   // always reached
    return { success: true, txSignature: null };
}
```

**Only call site — `server/socket-io/main.js` lines 686–691:**
```js
} else if (ms.status === MATCH_STATES.LOBBY) {
    // Not started yet — refund if applicable
    const wallet = ws.wallets[client.id]
    if (wallet && ws.amount > 0) {
        await refundWager(wallet, ws.amount)   // line 690 — only 2 args
    }
}
```

`matchId`, `playerOneAddress`, and `playerTwoAddress` are all `undefined` at the call site. The guard on line 241 evaluates as:

```
isEscrowEnabled() && undefined && undefined && undefined  →  false
```

The on-chain branch is never entered. The function returns `{ success: true, txSignature: null }` from the fallback path, giving the caller a spurious success signal.

**PDA derivation in `cancelMatchEscrow` — `server/services/escrow.js` lines 443–444:**
```js
const [escrowPDA] = getEscrowPDA(matchId);  // matchId would be undefined if reached
```

Even if the guard were somehow bypassed, passing `undefined` as `matchId` to `Buffer.from(matchId)` would throw a `TypeError`, causing the escrow to close with an unhandled error.

**`roomId` = `matchId` throughout the codebase.** `wagerStates` is keyed by `roomId`. `createMatchEscrow` is called with `roomId`. `cancelMatchEscrow` is called directly with `roomId` at the correctly-written DCA-01 deposit-timeout and even-disconnect paths (lines 638, 1073, 1336). The correct arguments are available in scope at line 690 — they are simply never passed.

**Correctly written sibling paths (for comparison):**
- Even-disconnect refund, `main.js` line 638:
  ```js
  await cancelMatchEscrow(roomId, p1w, p2w)
  ```
- DCA-01 deposit timeout, `main.js` lines 1073 and 1336:
  ```js
  await cancelMatchEscrow(roomId, p1wallet, p2wallet)
  ```

These paths call `cancelMatchEscrow` directly and correctly. The LOBBY-phase path calls `refundWager` (the wrapper) but omits the escrow arguments.

## Root Cause

Incomplete argument list at the `refundWager` call site (`main.js:690`). The function's 5-argument signature was expanded to support escrow cancellation (parameters 3–5), but the LOBBY-phase call site was never updated to supply those arguments. The internal guard condition silently swallows the omission by treating missing arguments as a "dev mode" signal to skip on-chain logic, then returns `success: true`, providing no indication to the caller that no actual refund occurred.

## Impact

In production (escrow enabled), a player disconnecting during the LOBBY phase (after the escrow PDA has been created and one or both players have submitted deposits) will not receive an on-chain refund. Deposited SOL is locked in the escrow PDA until the 48-hour permissionless reclaim window (`permissionlessReclaimEscrow`) expires. For a 0.5 SOL duel wager that is a per-incident loss of up to 1.0 SOL (both players) with no error logged and a spurious `{ success: true }` return value masking the failure.

The affected code path is the common one: a lobby disconnect before `startPick` fires (i.e., any player closing the tab or losing connection in the joining phase).

## Recommendation

Update `main.js` line 690 to supply all required arguments. The needed values are in scope at that code location:

```js
} else if (ms.status === MATCH_STATES.LOBBY) {
    // Not started yet — refund if applicable
    const wallet = ws.wallets[client.id]
    if (wallet && ws.amount > 0) {
        const p1wallet = ws.wallets[room.host?.socketId]
        const p2wallet = ws.wallets[room.player?.socketId]
        await refundWager(wallet, ws.amount, roomId, p1wallet, p2wallet)
    }
}
```

Note that `room` is available at line 576 (`const room = findRoom(roomId)`) and is already used in the enclosing block; it is accessible here. The guard inside `refundWager` will still gracefully skip the on-chain call if either wallet is `null` (i.e., the second player has not yet joined).

Additionally, consider adding an explicit warning log inside `refundWager` when `isEscrowEnabled()` is true but `matchId`/player addresses are missing, to catch future regressions:

```js
if (isEscrowEnabled() && (!matchId || !playerOneAddress || !playerTwoAddress)) {
    console.warn('[Solana] refundWager called without escrow params — on-chain refund skipped');
}
```
