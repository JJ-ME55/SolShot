## H075 — Wind Generation Predictability: CSPRNG + Timing Risk

**Verdict:** POTENTIAL

**Severity:** MEDIUM

**Evidence:**
- `server/services/physics.js:62-64` — Wind generation uses crypto.randomInt (CSPRNG):
  ```
  export function generateWind() {
      return crypto.randomInt(121) - 60;
  }
  ```
- Wind is generated per round server-side (cryptographically secure)
- Timing: Wind is sent to BOTH clients via `startRound` event
- Architecture document (ARCHITECTURE.md:9.2) — "wind sent to clients after shot commit" not validated
- Clients can theoretically predict shots if wind values are broadcast before lock-in

**Recommendation:** Verify wind is NOT sent to clients until after both players commit their shot angles/powers; consider committing wind value hash pre-round.
