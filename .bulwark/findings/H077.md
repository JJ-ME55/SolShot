## H077 — Weapon Array Integrity Server vs Client

**Verdict:** POTENTIAL

**Severity:** HIGH

**Evidence:**
`client/src/data/weapons.js` defines 15 weapons with static IDs (0, 25, 12, 20, 2, 10, 5, 15, 7, 11, 1, 17, 4, 16, 9). Server maintains WEAPON_CATALOG in `server/models/Weapon.js`. Both sources are independent (no shared definition).

If client sends weapon ID not in server's WEAPON_CATALOG (via `weaponPick`, `buyWeapon`, `shoot`), server checks `getWeapon(id)` but doesn't validate ownership. At `buyWeapon` (main.js:1507): "Unknown weapon" check exists, but for `weaponPick` and `shoot` handlers, no explicit weapon ID validation before physics simulation.

**Risk:** Client can submit arbitrary weapon IDs. Server may attempt physics processing on undefined weapon, causing silent failure or incorrect damage.

**Recommendation:** Validate weapon ID against WEAPON_CATALOG in all handlers before game logic execution. Maintain weapon definitions in single source (API endpoint or shared config).
