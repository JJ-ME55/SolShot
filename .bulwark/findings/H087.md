## H087 — Socket Event Ordering Assumptions

**Verdict:** POTENTIAL

**Severity:** HIGH

**Evidence:**
Socket handlers validate action state (match phase) via `validateAction()` in `match.js` but are inconsistent:
- `shoot` (main.js ~1700): Calls `validateAction(ms.status, 'shoot')`
- `giveTurn` (main.js ~2300): Calls `validateAction(ms.status, 'giveTurn')`
- But `weaponPick`, `angleChange`, `powerChange` (lines ~1635, ~1850, ~1870): **Only check auth flag**, do NOT validate match state

Result: Player in READY state can send `angleChange` → changes angle → server accepts and broadcasts. Then `fire` executes with modified angle in READY phase (before actual turn). Or: fire sent before ready → rejected, but fire sent after ready+round start can execute mid-setup.

No state guards on 14+ minor handlers. Race between state transitions and rapid event sends.

**Attack:** Send fire immediately after ready (before round officially starts). Rapid-fire setup events during opponent's turn.

**Recommendation:** Wrap ALL game-affecting handlers in `validateAction(ms.status, eventName)` checks. Use match state as sole authority for what events are valid.
