## H093 — Ghost Match Replay Attack

**Verdict:** NOT VULNERABLE

**Severity:** INFO

**Evidence:**
- Solana blockchain prevents transaction replay via nonce (if using blockhash as part of TX signature)
- On-chain escrow program (audited separately) uses PDA seeds ["match", match_id] for escrow account derivation
- server/services/escrow.js:39 — PROGRAM_ID hardcoded (prevents program ID spoofing)
- settleMatch signature includes Match account and program instruction signature (on-chain validation)

**Analysis:**
Potential replays are prevented at two layers:
1. **Transaction level:** Solana RPC rejects replayed TXs within blockhash expiry window (600 slots ~= 4 minutes)
2. **Account level:** PDA for each match is unique (["match", match_id]). Resending settleMatch on same PDA fails because account is closed (Close constraint in Anchor)

Tested path:
- First match settlement: Anchor settleMatch closes the escrow account via `close = ...` instruction
- Replayed settleMatch: TX signature may be replayed, but program checks account exists → account closed → settleMatch fails (account discriminator mismatch)

**Conclusion:** Properly guarded. No additional mitigations needed.

**Recommendation:** Document PDA closure as replay mitigation in code comments.
