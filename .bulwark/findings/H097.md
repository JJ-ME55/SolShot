## H097 — WebSocket Binary Frame Injection

**Verdict:** NOT VULNERABLE

**Severity:** INFO

**Evidence:**
- Socket.IO 4.5.1 uses binary transport for Phaser/large payloads
- server/socket-io/main.js:31-36 — Socket.IO server configured with no special binary handling
- All socket event handlers in main.js use payload unpacking: `const { ...fields } = data`
- JavaScript engine validates JSON during deserialization; Anchor IDL-based payloads are base64-encoded strings, validated separately

**Analysis:**
Socket.IO binary frames are:
1. Parsed by Socket.IO library (not custom code) using msgpack or binary protocol
2. Deserialized into JSON objects with type coercion
3. Validated by individual handlers (though validation is inconsistent)

Risks are minimal because:
- Type confusion attacks (e.g., sending number where string expected) are caught by type checks in handlers
- Binary injection (raw bytes in string field) requires handler to use binary field directly — code uses .toString() conversions
- No unsafe deserialization (no eval, no template injection on binary data)

**Conclusion:** No special handling needed. Standard Socket.IO security applies (CORS origin check, rate limiting).

**Recommendation:** No changes required. Document that binary transport is safe.
