## H105 — Progressive Wager Escalation

**Verdict:** NOT VULNERABLE

**Severity:** INFO

**Evidence:**
Wager validation is enforced on both room creation and play-again:

1. **createRoom** (main.js:1103-1180):
   - `validateMatchMode(mode, wager, matchLength)` (solana.js:51-65)
   - Checks: wager tier whitelist, min/max per mode, match format

2. **playAgainRequest** (main.js:2498-2570):
   - Reads existing room config: `paRounds = room.totalRounds`
   - Derives `paRoundType` and creates new room with same config
   - **Critical**: Does NOT change wager amount from `wagerStates[client.roomId]`
   - New room inherits original wager unchanged

3. **joinQueue** (main.js:1213+):
   - Also validates mode and wager before queue entry

Wager cannot escalate because:
- Room creation validates against MATCH_MODES
- Play-again reuses the same wager from the first match
- No handler modifies `wagerStates[roomId].amount` mid-match

**Recommendation:** No action required; wager amount is immutable per match.
