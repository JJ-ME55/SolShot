## H107 — Match State Machine Invalid Transition

**Verdict:** POTENTIAL

**Severity:** MEDIUM

**Evidence:**
State machine is strict but with exploitable edge cases:

1. **match.js:41-57** (`transitionState`):
   - Checks `validTransitions[currentState].includes(newState)`
   - Returns false if invalid; does NOT throw or enforce
   - **Caller responsibility**: main.js must check return value

2. **Transitions defined** (match.js:23-32):
   ```
   LOBBY → [WEAPON_SHOP, BATTLE, CANCELLED]
   BATTLE → [ROUND_END, SETTLING, CANCELLED]
   SETTLING → [COMPLETE, CANCELLED]
   COMPLETE → []
   CANCELLED → []
   ```

3. **Invalid transition handling** (main.js):
   - **playAgainRequest** (line 2505): Checks `validateAction()` before transition
   - **fire handler**: Does NOT validate before `transitionState(ms, MATCH_STATES.SETTLING)`
   - **disconnect cleanup** (line 583): Does NOT validate before settling

**Vulnerability**: If fire handler receives COMPLETE or SETTLED match state, `transitionState()` returns false silently. Code continues and attempts settlement on closed escrow PDA.

Example: Player A disconnects during settlement, escrow closes. Player B fires → attempts `SETTLING → COMPLETE` transition on already-COMPLETE state → silent failure → settlement retry cycle exhausted.

**Recommendation:** Add guards before transitionState; log/emit error on invalid transitions.
