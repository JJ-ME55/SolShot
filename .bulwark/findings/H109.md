## H109 — Escrow Dust Deposit Griefing

**Verdict:** CONFIRMED

**Severity:** HIGH

**Evidence:**
Server pays transaction fees for escrow creation but cannot force deposit:

1. **createMatchEscrow** (escrow.js:281-314):
   - Server authority signs and pays creation fee (~5,000 lamports)
   - Creates PDA at `["match", matchId]`
   - Both players receive deposit request via socket

2. **Deposit transaction** (escrow.js:326-372):
   - Server builds unsigned transaction for client to sign
   - Client may sign, fail to sign, or submit partial deposit
   - Server cannot enforce completion

3. **Attack vector** (joinQueue):
   - Attacker with 0 SOL joins queue (no balance check — H002)
   - Server creates escrow (pays creation TX fee)
   - Server sends deposit request to attacker
   - Legitimate opponent deposits
   - Attacker's deposit fails (no SOL)
   - 2-minute timeout expires (DCA-01: main.js:55-56)
   - Server calls `cancelMatchEscrow()` (pays cancellation fee)
   - Legitimate opponent gets refunded (minus gas)

**Cost amplification**:
- Rate limit: 3 createRoom per 60s per socket (main.js:515-523)
- Cost per griefing attempt: ~10,000 lamports (create + cancel)
- Attacker cost: 0 SOL (no deposit attempted)
- Victim cost: Gas for deposit + refund (~8,000 lamports)
- Server cost: 10,000 lamports per attempt

With 100 sockets per IP, attacker can trigger ~300 griefing attempts per minute = ~3M lamports/min (~$0.30/min on devnet).

**Recommendation:** Require balance check before accepting queue entries; reject 0-SOL wallets from wagered queues.
