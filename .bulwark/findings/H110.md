## H110 — WebSocket Heartbeat Manipulation

**Verdict:** NOT VULNERABLE

**Severity:** INFO

**Evidence:**
Socket.IO heartbeat (ping/pong) uses default configuration:

1. **index.js:31-36**: Server creates `new socket.Server()` without custom options:
   ```javascript
   const io = new socket.Server(server, { cors: { origin: CORS_ORIGINS, methods: ["GET", "POST"] } })
   ```

2. **Socket.IO defaults** (Socket.IO 4.5.1):
   - `pingInterval`: 25,000 ms (25 seconds)
   - `pingTimeout`: 60,000 ms (60 seconds)
   - Max idle: 85 seconds before disconnect

3. **Disconnect handling** (main.js:655+):
   - `client.on('disconnect')` handler exists
   - Cleans up room state, cancels escrow on active match
   - Re-authentication required on rejoin

4. **Attack surface**:
   - Attacker cannot extend heartbeat window beyond 60s without active events
   - Socket sends/receives ping every 25s (enforced client-side by Socket.IO)
   - No buffer overflow possible (heartbeat is fixed protocol)

**No vulnerability**: Default heartbeat timings are standard and secure. Disconnection handling is properly implemented.

**Recommendation:** No action required; heartbeat configuration is appropriate.
