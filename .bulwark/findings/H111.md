## H111 — Asymmetric Information via Room Peek

**Verdict:** POTENTIAL

**Severity:** MEDIUM

**Evidence:**
Room state is partially broadcast to all connected sockets:

1. **broadcastRooms** (main.js:~2400):
   - Called on room creation, deletion, player join/leave
   - Emits to `io.sockets.emit('rooms', roomList)`
   - **No namespace restriction** — all connected sockets receive the list

2. **Room data exposed**:
   - `roomId`, `host name/color`, `player name/color`, `totalRounds`, `wagerAmount`
   - **Game state NOT exposed**: HP, weapons, terrain, match status

3. **Information leakage**:
   - Non-participant can see which wallets are in which rooms (indirectly via host/player names)
   - Can see all active wagered matches and wager amounts
   - **Example**: Attacker sees "$0.25 Duel in progress" → knows winner will receive ~$0.225

4. **Confidentiality impact**:
   - Does NOT reveal game state (no decision advantage)
   - Reveals financial information (wager amounts, match timing)
   - Could be used for wallet clustering/deanonymization

5. **Missing guard**:
   - No check that receiver is in the room
   - broadcastRooms uses `io.sockets.emit()` (global), not `io.sockets.in(roomId).emit()` (scoped)

**Recommendation:** Filter broadcastRooms to only emit active non-wagered matches; remove wager amount from broadcast; use Socket.IO rooms for scoped emission.
