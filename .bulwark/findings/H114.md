## H114 — Client-Predicted Physics Desync

**Verdict:** NOT VULNERABLE

**Severity:** INFO

**Evidence:**
Server is authoritative on physics. Client sends only angle and power; server runs `processShot()` from server/services/physics.js. Server broadcasts results to both players (server/socket-io/main.js:1831-1850). Client does NOT run its own projectile simulation — it receives server-computed trajectory and renders it. Phaser.js client-side animation plays the received trajectory, not a predicted one.

Verified: No client-side physics engine found in `client/src/services/` or BattleScreen.js.

**Recommendation:** Maintain server-authoritative architecture; monitor for client PRs attempting to add client-side prediction.

---

**Notes:** This is defense-in-depth correct. The position drift vulnerability (C-9) exists, but does not involve client physics — it involves server accepting out-of-bounds position updates.
