## H115 — Event Storm via Automated Socket Client

**Verdict:** POTENTIAL

**Severity:** HIGH

**Evidence:**
Rate limiting is HTTP-level only (express-rate-limit on /api endpoints, server/index.js:100-107). Socket.IO events have zero per-connection or global rate limiting. An attacker can:

1. Connect with valid socket
2. Emit `positionUpdate` 1000x/sec (no throttle)
3. Emit `shoot` repeatedly without turn validation (server/socket-io/main.js:~1820+ checks currentTurn but accepts rapid-fire on same turn)
4. Emit `angleChange`/`powerChange` at wire speed (no delay)
5. Fill server memory/CPU

Solana validator also unprotected from event flood causing RPC timeout cascade.

**Recommendation:** Implement per-socket rate limiting on all game events (e.g., 30 events/sec max). Consider Socket.IO middleware: `io.use()` with event throttle map.

---

**Notes:** `maxHttpBufferSize` not configured (default 1e6 = 1MB), but not primary defense here. Event storm is orthogonal to HTTP buffer — socket.io will queue and process every event regardless.
