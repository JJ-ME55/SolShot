Rewrite `tests/solshot-escrow.ts` to comprehensively test the hardened program. Use the existing test file as a structural base but expand significantly. The test file uses `@coral-xyz/anchor`, `@solana/web3.js`, `chai`, and `ts-mocha`.

**Test structure (in order of execution):**

**Setup (before all):**
- Fund test wallets: playerOne, playerTwo, treasury, ops, randomWallet
- Derive configPDA using `PublicKey.findProgramAddressSync([Buffer.from("config")], program.programId)`
- Derive match PDAs for each test scenario using unique match IDs (`test-{scenario}-${runId}`)

**Test Group 1: Config Initialization**
1. `initializes config PDA` — Call `program.methods.initializeConfig(authority.publicKey, treasury.publicKey, ops.publicKey).accounts({ config: configPDA, payer: authority.publicKey, systemProgram }).rpc()`. Fetch config and verify all fields match.
2. `rejects re-initialization` — Try calling initializeConfig again. Should fail (Anchor `init` constraint prevents re-init).

**Test Group 2: Config Management**
3. `updates config authority` — Call updateConfig with new_authority = Some(newKeypair.publicKey), new_treasury = None, new_ops = None. Verify only authority changed. Then update back to original authority.
4. `non-authority cannot update config` — Try updateConfig signed by playerOne. Should fail.

**Test Group 3: Pause Mechanism**
5. `authority can pause program` — Call pauseProgram. Fetch config, verify is_paused = true.
6. `create_match fails when paused` — Try creating a match while paused. Should fail with ProgramPaused error.
7. `authority can unpause program` — Call unpauseProgram. Fetch config, verify is_paused = false.

**Test Group 4: Match Creation Guards**
8. `creates a match escrow with valid params` — Standard create + verify fields. Include wager of 0.002 SOL (2_000_000 lamports, well above MIN). Verify activated_at is 0 initially.
9. `rejects match where authority is a player` — create_match with player_one = authority.publicKey. Should fail with AuthorityAsPlayer.
10. `rejects wager below minimum` — create_match with wager_lamports = 1_000 (below 10_000 MIN). Should fail with WagerTooSmall.
11. `rejects wager above maximum` — create_match with wager_lamports = 200_000_000_000 (above 100 SOL MAX). Should fail with WagerTooLarge.

**Test Group 5: Deposit + Active Transition**
12. `player one deposits wager` — Standard deposit, verify playerOneDeposited = true, state = AwaitingDeposits.
13. `player two deposits → match Active` — Standard deposit, verify both deposited, state = Active, activated_at > 0.
14. `rejects double deposit` — Try P1 depositing again. Should fail.
15. `non-player cannot deposit` — Try randomWallet depositing. Should fail.

**Test Group 6: Settlement with Constraints**
16. `settles match with correct 90/7/3 split` — Standard settle with player_one as winner. Verify balance changes match expected amounts. Use tolerance for rent.
17. `rejects settle with invalid winner` — Create + deposit a new match. Try settling with winner = randomWallet (not a player). Should fail with InvalidWinner.
18. `rejects settle with wrong treasury` — Create + deposit a new match. Try settling with treasury = randomWallet (not config.treasury). Should fail with InvalidTreasury.
19. `rejects settle with wrong ops` — Try settling with ops = randomWallet. Should fail with InvalidOps.
20. `non-authority cannot settle` — Try settling signed by playerOne. Should fail with Anchor has_one constraint.

**Test Group 7: Cancel with Authority Restriction**
21. `authority cancels AwaitingDeposits match` — Create a match (no deposits), authority cancels. Should succeed.
22. `authority CANNOT cancel Active match` — Create + both deposit. Authority tries to cancel. Should fail with Unauthorized (OC-05).
23. `player cancels AwaitingDeposits with refund` — Create, P1 deposits, P1 cancels. Should succeed with refund.

**Test Group 8: Math Verification (off-chain)**
24. `settlement math: no dust loss across wager tiers` — Same as existing test 8 but expanded wager tiers.

**Implementation notes:**
- Each negative test must create its OWN match (unique matchId) to avoid PDA collisions
- After settle/cancel tests that close escrows, subsequent tests cannot reuse those PDAs
- Use `try/catch` pattern for negative tests: call should throw, catch the error, assert it contains the expected error string. If no throw, `assert.fail("should have thrown")`
- Fund wallets with enough SOL for all test matches (0.01 SOL each is sufficient for the small wagers)
- Config PDA is shared across all tests — initialized once in the first test
- For test 18/19 (wrong treasury/ops), the config has treasury and ops set to specific keypairs. Pass different addresses in the settle call to trigger the constraint error.
- For test 22 (authority cancel Active), the match must first be created and both players must deposit to reach Active state, then authority tries to cancel
- Clean up by settling any Active matches at the end of tests to avoid dangling PDAs (not strictly necessary on localnet but good practice)
