**SA-04 — Remove fire handler position writeback:**

In the fire handler (inside `safeHandler`), find the position tolerance block (lines ~1724-1734). Currently it reads:
```js
if (data.position && typeof data.position === 'object' &&
    Number.isFinite(data.position.x) && Number.isFinite(data.position.y)) {
    const dx = Math.abs(data.position.x - serverPos.x)
    const dy = Math.abs(data.position.y - serverPos.y)
    if (dx <= 400 && dy <= 200) {
        startX = data.position.x
        startY = data.position.y
        serverPos.x = startX
        serverPos.y = startY
    }
}
```

Delete the two writeback lines:
```js
serverPos.x = startX
serverPos.y = startY
```

These lines write the CLIENT's reported position back into the server's authoritative position state (`room.host.pos` or `room.player.pos`), allowing a client to drift the server's position over time. The fire handler should USE client position for THIS shot's starting point (within tolerance), but never PERSIST it back to server state.

The remaining code (using `startX`/`startY` for trajectory calculation) is correct — it allows minor terrain-walk discrepancies while keeping the server position authoritative for future turns.

Add a comment:
```js
// SA-04: Do NOT write startX/startY back to serverPos — server position is authoritative (DB: H034, H035)
```

In the `positionUpdate` handler (line ~2195), add distance validation that only applies during BATTLE state. After the existing `if (!room) return` check, add:

```js
// SA-04: Distance validation during battle — reject teleportation (DB: H034, H035)
const ms = matchStates[client.roomId]
if (ms && ms.status === MATCH_STATES.BATTLE) {
    const isHost = room.host && room.host.socketId === client.id
    const currentPos = isHost ? room.host.pos : (room.player ? room.player.pos : null)
    if (currentPos) {
        const dx = Math.abs(clampedX - currentPos.x)
        const dy = Math.abs(clampedY - currentPos.y)
        if (dx > 400 || dy > 200) {
            // Reject — position jump too large (likely cheating or desync)
            return
        }
    }
}
```

Place this BEFORE the existing host/player position assignment block. The distance thresholds (400px horizontal, 200px vertical) match the fire handler's tolerance values and account for blast knockback physics.

The validation only applies during BATTLE state because during setup/lobby, positions are set by terrain generation and may jump legitimately. During BATTLE, positions should only change by knockback physics (which are bounded) and stepping (80px per step, max 4 steps = 320px).
