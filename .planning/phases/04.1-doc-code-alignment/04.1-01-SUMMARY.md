# Phase 4.1 Plan 01: Doc-Code Alignment (Escrow Deposit Timer + HP Settlement + Dead Code) Summary

**One-liner:** 2-min deposit countdown with cancelMatchEscrow timeout, HP-based disconnect forfeit settlement, and raydium.js dead code removal.

## What Was Built

### DCA-01: Deposit Countdown Timer

Added `depositTimers` map and `DEPOSIT_TIMEOUT_MS = 120_000` constant alongside the existing `shopTimers`, `turnTimers`, and `disconnectTimers` maps.

Both escrow deposit paths (direct `joinRoom` and matchmaking `joinQueue`) now:
1. Compute `depositDeadline = Date.now() + DEPOSIT_TIMEOUT_MS` before emitting
2. Include `depositDeadlineMs: depositDeadline` in both `escrowDeposit` events so clients can render a countdown
3. Start a `depositTimers[roomId]` setTimeout that on expiry:
   - Checks if both deposits are already confirmed (no-op if so)
   - Calls `cancelMatchEscrow(roomId, p1wallet, p2wallet)` if escrow enabled
   - Emits `escrowDepositTimeout` to all clients in the room
   - Calls `removeRoom(roomId)` and cleans up the Socket.IO room

The `escrowDepositConfirm` handler now clears `depositTimers[rid]` inside the `if (hostDeposited && playerDeposited)` block — preventing a spurious timeout after a legitimate double-deposit.

`removeRoom()` now also clears `depositTimers[roomId]` as a safety net for any other teardown path.

### DCA-03: HP-Based Disconnect Settlement

Modified `cleanupRoom()` — specifically the `withLock` settlement block — to check `reason` before deciding winner:

- `reason === 'leave'` or `'disconnect'`: unconditional forfeit to opponent (intentional quit)
- `reason === 'reconnect_timeout'`: HP-based decision chain:
  1. **roundWins**: player with more round wins wins the wager
  2. **HP** (tie on rounds): player with more HP wins
  3. **scores** (tie on HP): player with higher score wins
  4. **all equal**: `shouldRefund = true` → `cancelMatchEscrow` + `matchSettled { type: 'refund', reason: 'even_disconnect' }`

HP defaults to 250 (starting value) when `currentMs.hp[id]` is undefined — prevents a disconnecting player from appearing to "have no HP" and losing unfairly.

### DCA-04: Dead Code Removal

Deleted `server/services/raydium.js` — a config-only reference file for a Raydium pool integration that was never imported anywhere. Confirmed via grep across `server/` and `client/`. No import graph changes.
