server-side JavaScript changes (deposit countdown timer, HP-based disconnect settlement, dead

HP-based disconnect logic already has access to `matchStates[roomId].hp` at the point where

pattern already present in `cancel_match` (lamport transfer + close). Raydium.js is confirmed
dead — zero imports across the entire codebase.

**Primary recommendation:** Implement DCA-01, DCA-03, DCA-04 in a single server file edit
session. DCA-02 (Anchor) is an isolated program change; plan it as a separate task because it
requires `anchor build` and IDL re-copy.

### Deposit Countdown (DCA-01)

**Pattern: Named in-memory timer map, same as existing `shopTimers` and `disconnectTimers`**

A new `depositTimers` map is needed in main.js. When both players have joined and the escrow
deposit transactions are sent, a 2-minute (120s) server-side timer starts. If only one player
has deposited when it fires, `cancelMatchEscrow()` is called and both players receive
`escrowDepositTimeout` event.

Key insertion point: immediately after the `escrowDeposit` events are emitted to both
players in `joinRoom` handler (line ~968-984 in main.js). The same pattern exists in
`endShopPhase` and `disconnectTimers`.

**Existing pattern to follow:**
```javascript
// Existing (shopTimers pattern) — ~line 134

// ...
shopTimers[roomId] = setTimeout(() => { endShopPhase(io, roomId) }, SHOP_DURATION * 1000)
```

**New pattern (DCA-01):**
```javascript
// Add at top of main.js alongside other timer constants
const DEPOSIT_TIMEOUT_MS = 120_000 // 2 minutes

// In-memory timer map (top of file alongside shopTimers)
var depositTimers = {}

// After emitting 'escrowDeposit' to both players in joinRoom:
depositTimers[roomId] = setTimeout(async () => {
    delete depositTimers[roomId]
    const ws = wagerStates[roomId]
    const room = findRoom(roomId)
    if (!room || !ws) return
    // Check if BOTH have deposited — if yes, timer is moot
    if (ws.deposits && ws.deposits[room.host?.socketId] && ws.deposits[room.player?.socketId]) return
    // Only one (or neither) deposited — cancel escrow
    const p1wallet = ws.wallets[room.host?.socketId]
    const p2wallet = ws.wallets[room.player?.socketId]
    if (p1wallet && p2wallet) {
        await cancelMatchEscrow(roomId, p1wallet, p2wallet)
    }
    io.sockets.in(roomId).emit('escrowDepositTimeout', { roomId })
    await removeRoom(roomId)
}, DEPOSIT_TIMEOUT_MS)
```

**Cancel the timer** in `escrowDepositConfirm` handler when both deposits are confirmed
(around line 1666). Also clear it in `removeRoom()` and the matchmaking path.

**Client-side display:** The `escrowDeposit` event should include a `depositDeadlineMs`
field (Date.now() + DEPOSIT_TIMEOUT_MS) so both clients can display a countdown. The
existing `reconnectWindowMs` pattern (line 664) demonstrates this approach.

### Permissionless Reclaim Instruction (DCA-02)

**Pattern: New Anchor instruction, no signer restriction, 2x timeout check**

The existing `cancel_match` instruction requires the caller to be either the authority
(AwaitingDeposits only) or a player (after 24h timeout). The new `permissionless_reclaim`
instruction:
- Takes NO specific caller requirement (anyone can call it)
- Requires 2x TIMEOUT_SECONDS (48 hours) to have elapsed from `created_at` or `activated_at`
- Refunds only deposited amounts (same logic as cancel_match)
- Closes the PDA to the caller as the rent recipient (incentivizes calling)

**Critical design notes:**
- Keep `permissionless_reclaim` SEPARATE from `cancel_match` — separate instruction, separate
  account struct, separate logic. Do not modify `cancel_match`.
- The caller receives the rent lamports (PDA close) as the economic incentive to trigger it.
  This is the standard Solana "crank" pattern for permissionless cranks.
- Must use `close = caller` in the account constraint to return rent to caller.
- The `config` PDA is NOT needed (no authority check, no pause guard required for reclaim —
  the time-lock is the security mechanism).
- TIMEOUT_SECONDS is currently 86400 (24h). Permissionless reclaim uses 2x = 172800 (48h).

**Rust implementation pattern:**
```rust
// Add constant at top of lib.rs
const PERMISSIONLESS_RECLAIM_TIMEOUT: i64 = TIMEOUT_SECONDS * 2; // 48 hours

pub fn permissionless_reclaim(ctx: Context<PermissionlessReclaim>) -> Result<()> {
    // Read values before mutable borrow
    let player_one_deposited = ctx.accounts.escrow.player_one_deposited;
    let player_two_deposited = ctx.accounts.escrow.player_two_deposited;
    let wager_lamports = ctx.accounts.escrow.wager_lamports;
    let match_id = ctx.accounts.escrow.match_id.clone();

    // Must not already be settled or cancelled
    require!(
        ctx.accounts.escrow.state != MatchState::Settled
        && ctx.accounts.escrow.state != MatchState::Cancelled,
        EscrowError::InvalidState
    );

    // Compute timeout reference (same pattern as cancel_match)
    let timeout_reference = if ctx.accounts.escrow.activated_at > 0 {
        ctx.accounts.escrow.activated_at
    } else {
        ctx.accounts.escrow.created_at
    };

    let reclaim_deadline = timeout_reference
        .checked_add(PERMISSIONLESS_RECLAIM_TIMEOUT)
        .ok_or(EscrowError::ArithmeticOverflow)?;

    require!(
        Clock::get()?.unix_timestamp > reclaim_deadline,
        EscrowError::TooEarlyToReclaim // new error code
    );

    // OC-10: set terminal state BEFORE transfers
    {
        let escrow = &mut ctx.accounts.escrow;
        escrow.state = MatchState::Cancelled;
    }

    // Refund deposited amounts to each player
    if player_one_deposited {
        **ctx.accounts.escrow.to_account_info().try_borrow_mut_lamports()? -= wager_lamports;
        **ctx.accounts.player_one.to_account_info().try_borrow_mut_lamports()? += wager_lamports;
    }
    if player_two_deposited {
        **ctx.accounts.escrow.to_account_info().try_borrow_mut_lamports()? -= wager_lamports;
        **ctx.accounts.player_two.to_account_info().try_borrow_mut_lamports()? += wager_lamports;
    }

    emit!(MatchCancelled {
        match_id,
        refunded_one: player_one_deposited,
        refunded_two: player_two_deposited,
    });

    Ok(())
}
```

**Account struct for PermissionlessReclaim:**
```rust
#[derive(Accounts)]
pub struct PermissionlessReclaim<'info> {
    #[account(
        mut,
        seeds = [b"match", escrow.match_id.as_bytes()],
        bump = escrow.bump,
        close = caller,  // Rent goes to whoever triggers the reclaim
    )]
    pub escrow: Account<'info, MatchEscrow>,

    /// CHECK: Caller is permissionless — anyone can trigger after timeout
    #[account(mut)]
    pub caller: Signer<'info>,

    /// CHECK: Must match escrow.player_one for refund
    #[account(
        mut,
        constraint = player_one.key() == escrow.player_one @ EscrowError::InvalidPlayer,
    )]
    pub player_one: UncheckedAccount<'info>,

    /// CHECK: Must match escrow.player_two for refund
    #[account(
        mut,
        constraint = player_two.key() == escrow.player_two @ EscrowError::InvalidPlayer,
    )]
    pub player_two: UncheckedAccount<'info>,

    pub system_program: Program<'info, System>,
}
```

**Server-side JS wrapper (escrow.js) — new function:**
```javascript
export async function permissionlessReclaimEscrow(matchId, callerAddress, playerOneAddress, playerTwoAddress) {
    if (!program) return { success: false, error: 'Escrow not initialized' };
    try {
        const caller = new PublicKey(callerAddress);
        const playerOne = new PublicKey(playerOneAddress);
        const playerTwo = new PublicKey(playerTwoAddress);
        const [escrowPDA] = getEscrowPDA(matchId);

        const tx = await program.methods
            .permissionlessReclaim()
            .accounts({
                escrow: escrowPDA,
                caller: caller,
                playerOne: playerOne,
                playerTwo: playerTwo,
                systemProgram: PublicKey.default,
            })
            .rpc();

        return { success: true, txSignature: tx };
    } catch (err) {
        console.error(`[Escrow] permissionlessReclaim failed for ${matchId}:`, err.message);
        return { success: false, error: err.message };
    }
}
```

Note: This is a server-exposed function (admin/recovery tool), not called from normal match
flow. The instruction is on-chain and can be called by any Solana wallet after 48h.

### HP-Based Disconnect Settlement (DCA-03)

**Pattern: Read matchStates[roomId].hp and roundWins at the forfeit decision point**

**Current behavior (line ~668-692 in main.js):**
When the 30s reconnect timer fires, it calls `cleanupRoom(fakeClient, io, 'reconnect_timeout')`.
`cleanupRoom` (line ~550-634) unconditionally calls `settleMatch(opponentWallet, disconnectorWallet, ...)`.
The opponent always wins — no HP check.

**Required behavior (DCA-03):**
1. Check HP and roundWins at the moment the reconnect timer fires
2. Player with higher HP wins
3. If genuinely even (same HP, same roundWins) → refund both via `cancelMatchEscrow`
4. Apply only to connection drops (reconnect timeout path) — intentional quits (`leaveRoom`)
   keep the current unconditional forfeit behavior

**Where to add the logic:**
The `cleanupRoom` function already receives a `reason` parameter (`'reconnect_timeout'` vs
`'leave'` vs `'disconnect'`). The HP-check branch should be inside `cleanupRoom` when
`reason === 'reconnect_timeout'` and the match has a wager active.

**The `matchStates[roomId]` object has all needed fields at this point:**
- `ms.hp` — `{ [socketId]: number }` — current HP per player
- `ms.roundWins` — `{ [socketId]: number }` — rounds won per player
- `ms.scores` — `{ [socketId]: number }` — damage dealt (tiebreaker)

**Implementation pattern within cleanupRoom:**

```javascript
// In cleanupRoom, inside the wager forfeit block:
// if (ws && ws.amount > 0 && ms) { ... }

if (reason === 'reconnect_timeout' && ws && ws.amount > 0 && ms &&
    (ms.status === MATCH_STATES.BATTLE || ms.status === MATCH_STATES.WEAPON_SHOP)) {

    await withLock(`settle:${roomId}`, async () => {
        const currentMs = matchStates[roomId]
        const currentRoom = findRoom(roomId)
        if (!currentMs || currentMs.status === MATCH_STATES.SETTLING || currentMs.status === MATCH_STATES.COMPLETE) return

        transitionState(currentMs, MATCH_STATES.SETTLING)

        const opponentId = client.isHost
            ? (currentRoom.player ? currentRoom.player.socketId : null)
            : (currentRoom.host ? currentRoom.host.socketId : null)
        const disconnectorWallet = ws.wallets[client.id]
        const opponentWallet = opponentId ? ws.wallets[opponentId] : null

        if (opponentWallet && disconnectorWallet) {
            // HP-based determination for connection drops (DCA-03)
            const disconnectorHp = currentMs.hp[client.id] ?? 0
            const opponentHp = opponentId ? (currentMs.hp[opponentId] ?? 0) : 0
            const disconnectorRoundWins = currentMs.roundWins[client.id] || 0
            const opponentRoundWins = opponentId ? (currentMs.roundWins[opponentId] || 0) : 0
            const disconnectorScore = currentMs.scores[client.id] || 0
            const opponentScore = opponentId ? (currentMs.scores[opponentId] || 0) : 0

            // Determine winner or refund
            let winnerWallet = null
            let loserWallet = null
            let isRefund = false

            if (opponentRoundWins !== disconnectorRoundWins) {
                // Round wins decide
                if (opponentRoundWins > disconnectorRoundWins) {
                    winnerWallet = opponentWallet
                    loserWallet = disconnectorWallet
                } else {
                    winnerWallet = disconnectorWallet
                    loserWallet = opponentWallet
                }
            } else if (opponentHp !== disconnectorHp) {
                // HP decides
                if (opponentHp > disconnectorHp) {
                    winnerWallet = opponentWallet
                    loserWallet = disconnectorWallet
                } else {
                    winnerWallet = disconnectorWallet
                    loserWallet = opponentWallet
                }
            } else if (opponentScore !== disconnectorScore) {
                // Score (damage dealt) as final tiebreaker
                if (opponentScore > disconnectorScore) {
                    winnerWallet = opponentWallet
                    loserWallet = disconnectorWallet
                } else {
                    winnerWallet = disconnectorWallet
                    loserWallet = opponentWallet
                }
            } else {
                // Genuinely even — refund both
                isRefund = true
            }

            if (isRefund) {
                // Cancel escrow — refund both
                const p1wallet = ws.wallets[currentRoom.host?.socketId]
                const p2wallet = ws.wallets[currentRoom.player?.socketId]
                const cancelResult = await cancelMatchEscrow(roomId, p1wallet, p2wallet)
                transitionState(currentMs, cancelResult.success ? MATCH_STATES.CANCELLED : MATCH_STATES.CANCELLED)
                if (opponentId) {
                    io.to(opponentId).emit('matchSettled', {
                        type: 'disconnect_refund',
                        reason: 'Even score at disconnect — both players refunded',
                        txSignature: cancelResult.txSignature
                    })
                }
            } else {
                // Settle with HP-determined winner
                const settlementResult = await settleMatch(winnerWallet, loserWallet, ws.amount, roomId)
                if (settlementResult.success) {
                    transitionState(currentMs, MATCH_STATES.COMPLETE)
                    if (opponentId) {
                        io.to(opponentId).emit('matchSettled', {
                            type: 'disconnect_forfeit',
                            winner: opponentId, // if opponentWallet won
                            settlement: settlementResult.settlement,
                            txSignature: settlementResult.txSignature
                        })
                    }
                } else {
                    transitionState(currentMs, MATCH_STATES.CANCELLED)
                    await handleSettlementFailure(roomId, currentRoom, ws, settlementResult.error)
                }
            }
        }
    })
}
```

**Important:** The current `cleanupRoom` code runs this same block for BOTH `'reconnect_timeout'`
and `'leave'` cases (it does NOT have a reason check — it checks `ws.amount > 0 && ms`). The
refactoring must preserve the existing `'leave'` path (unconditional forfeit to opponent) and
only add HP logic to the `'reconnect_timeout'` path. The simplest approach: split the
settlement logic into two code paths based on `reason`.

## Common Pitfalls

### Pitfall 1: Deposit timer fires after match is already active
**What goes wrong:** Timer fires after both players deposited but `ws.deposits` check is missing.
**How to avoid:** At timer fire time, re-read `ws.deposits` and bail if both are confirmed.
**Code guard:**
```javascript
if (ws.deposits && ws.deposits[room.host?.socketId] && ws.deposits[room.player?.socketId]) return
```

### Pitfall 2: Deposit timer not cleared in all removal paths
**What goes wrong:** Timer fires after room was already cleaned up, attempts cancel on closed PDA.
**How to avoid:** Add `clearTimeout(depositTimers[roomId]); delete depositTimers[roomId]` in:
- `removeRoom()`
- `escrowDepositConfirm` handler when both confirmed
- Matchmaking path (if room is created then destroyed via queue)
**Warning sign:** `[Escrow] cancelMatch failed` logs appearing 2 minutes after normal matches.

### Pitfall 3: HP at 0 is not "dead" — it means the player lost, not "no data"
**What goes wrong:** HP of 0 is valid game state (player died). Treating it as "not initialized"
causes wrong refund decisions.
**How to avoid:** Use `?? 0` not `|| 0` for HP reads. If HP is missing from the map, default
0 is still a valid (dead) value for comparison purposes. The `matchStates[roomId].hp` map
is populated in the `startMatch` / round initialization flow.

### Pitfall 4: Rust borrow checker in permissionless_reclaim
**What goes wrong:** Reading `escrow.wager_lamports` after mutable borrow of `escrow` for
state change.
**How to avoid:** Read ALL values into locals BEFORE the `{ let escrow = &mut ctx.accounts.escrow; ... }`
block. This pattern is already established in lib.rs (settle_match and cancel_match both do this).

### Pitfall 5: IDL not updated after anchor build
**What goes wrong:** Server uses old IDL that doesn't have `permissionless_reclaim` method.
Calls will fail with "Method not found" at runtime.
**How to avoid:** The plan must include explicit step: after `anchor build` succeeds, copy
`target/idl/solshot_escrow.json` to `server/idl/solshot_escrow.json`. Then restart server.
**Warning sign:** `TypeError: program.methods.permissionlessReclaim is not a function`

### Pitfall 6: cancel_match requires authority or player signature — cannot be called from timer
**What goes wrong:** `cancelMatchEscrow()` uses the server keypair as `caller` — this is valid
because the server keypair IS the authority, and authority can cancel AwaitingDeposits state.
So the deposit timeout calling `cancelMatchEscrow` works IF the escrow is still in AwaitingDeposits.
**If one player has deposited** and the PDA is still in AwaitingDeposits state (not Active),
`cancel_match` with authority as caller still works — authority can cancel AwaitingDeposits.
Only after BOTH deposit (Active state) can authority NOT cancel. So the deposit timer path
(cancel before both deposit) is always valid for authority-caller.

### Pitfall 7: `leaveRoom` vs `reconnect_timeout` must remain distinct
**What goes wrong:** HP-based logic applied to intentional quits (leaveRoom) is unfair — the
quitter is choosing to leave and should forfeit unconditionally.
**How to avoid:** Only apply HP-based logic when `reason === 'reconnect_timeout'`. Keep
existing unconditional forfeit for `reason === 'leave'` and `reason === 'disconnect'` (immediate
disconnect without reconnect window — i.e., no wallet or not in BATTLE state).

## Open Questions

1. **Where do clients display the deposit countdown?**
   - What we know: The `escrowDeposit` event is received by both LobbyScreen and BattleScreen
   - What's unclear: Which screen is visible during deposit wait — still in lobby or transitioning?
   - Recommendation: Send `depositDeadlineMs: Date.now() + DEPOSIT_TIMEOUT_MS` with the
     `escrowDeposit` event. Let the client handle display. Keep server-side logic clean.

2. **Should `permissionless_reclaim` check `is_paused`?**
   - What we know: It's a recovery mechanism for abandoned escrows
   - What's unclear: Whether a paused program should block recovery
   - Recommendation: Do NOT add pause guard. Reclaim is a safety valve — should work even
     when program is paused. Consistent with the philosophy: "reclaim protects players from
     stuck funds."

3. **HP-based logic during WEAPON_SHOP state**
   - What we know: `cleanupRoom` checks `ms.status === MATCH_STATES.WEAPON_SHOP` for forfeit
   - What's unclear: HP values during weapon shop (between rounds) — `matchStates[roomId].hp`
     holds end-of-round HP, which is meaningful for comparison
   - Recommendation: Use HP as-is. If it's weapon shop between rounds, HP from the last round
     is still a valid game-state indicator. Round wins is a more reliable metric here.
