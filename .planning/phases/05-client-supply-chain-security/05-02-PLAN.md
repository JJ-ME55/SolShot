<objective>
Self-host the Telegram SDK to eliminate external CDN dependency (CS-02) and enable Content Security Policy on both the server (Helmet) and client (meta tag) to prevent script injection (CS-03).

Purpose: Prevent arbitrary script injection via CSP headers (DB: H031), and pin the Telegram SDK to a known version so external updates cannot break or compromise the app.

**CS-02 deviation note:** The ROADMAP success criterion says "integrity attribute with SRI hash." Research found the official `telegram.org/js/telegram-web-app.js` URL is not versionable — Telegram updates it in-place, so SRI would break unpredictably. Self-hosting the SDK at the same origin provides equivalent-or-stronger protection (no external CDN dependency at all) and satisfies the security intent of CS-02. The ROADMAP success criterion text should be updated after execution to reflect self-hosting as the chosen mitigation.

Output: Telegram SDK served from `/js/telegram-web-app.js` (same origin); CSP enabled via both Helmet and meta tag; inline scripts eliminated via `INLINE_RUNTIME_CHUNK=false`.
</objective>

**Step 2: Update index.html to use self-hosted SDK.**

In `client/public/index.html`, replace line 7:
```html
    <script src="https://telegram.org/js/telegram-web-app.js"></script>
```
With:
```html
    <script src="%PUBLIC_URL%/js/telegram-web-app.js"></script>
```

This uses CRA's `%PUBLIC_URL%` placeholder which resolves to the correct path in both dev and production builds.

**Step 3: Add CSP meta tag to index.html.**

After the `<meta name="viewport" ...>` tag (line 6) and before the Telegram script tag, add a CSP meta tag:
```html
    <meta http-equiv="Content-Security-Policy" content="default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com; img-src 'self' data: blob:; connect-src 'self' https://api.devnet.solana.com wss://api.devnet.solana.com https://api.mainnet-beta.solana.com wss://api.mainnet-beta.solana.com https://solshot-server.onrender.com wss://solshot-server.onrender.com ws://localhost:5001 wss://localhost:5001; frame-src 'none'; object-src 'none'; base-uri 'self';" />
```

**CSP directive rationale:**
- `script-src 'self'` — only same-origin scripts (no inline, no eval, no external CDN). This is the primary protection against H031.
- `style-src 'self' 'unsafe-inline'` — React and Phaser use inline styles extensively; blocking inline styles would break the UI.
- `font-src` — Google Fonts if used, or just `'self'`.
- `img-src 'self' data: blob:` — game uses data URIs for canvas/Phaser sprites and blob URLs.
- `connect-src` — Explicit Solana RPC endpoints (devnet + mainnet), Socket.IO server (Render production + localhost dev), all via specific origins. No bare `ws:` / `wss:` (those would allow WebSocket connections to any host, defeating CSP protection).
- `frame-src 'none'` — no iframes allowed (clickjacking defense).
- `object-src 'none'` — no plugins/Flash.
- `base-uri 'self'` — prevents base tag injection.

**Important:** `'unsafe-eval'` is NOT included. Phaser 3.55.2 has a try/catch around `new Function()` that falls back to `window` — it works without eval. CRA production builds use `source-map` devtool, NOT `eval-source-map`.

**Step 4: Set INLINE_RUNTIME_CHUNK=false in client env files.**

CRA injects an inline script in production builds for the runtime chunk. This would violate the `script-src 'self'` CSP directive. Setting `INLINE_RUNTIME_CHUNK=false` forces CRA to emit the runtime as a separate `.js` file instead.

Add to `client/.env`:
```
# CS-03: Prevent CRA from injecting inline scripts (CSP compliance)
INLINE_RUNTIME_CHUNK=false
```

Add to `client/.env.example`:
```
# CS-03: Prevent CRA from injecting inline scripts (CSP compliance)
INLINE_RUNTIME_CHUNK=false
```

<task type="auto">
  <name>Task 2: Enable Helmet CSP on server (CS-03 server-side)</name>
  <files>server/index.js</files>
  <action>
Replace the current helmet configuration in `server/index.js` (lines 38-41):
```js
app.use(helmet({
    contentSecurityPolicy: false,  // CSP handled by client/CDN
    crossOriginEmbedderPolicy: false,
}))
```

With an explicit CSP configuration:
```js
// CS-03: Enable Content Security Policy (DB: H031)
app.use(helmet({
    contentSecurityPolicy: {
        directives: {
            defaultSrc: ["'self'"],
            scriptSrc: ["'self'"],
            styleSrc: ["'self'", "'unsafe-inline'"],
            imgSrc: ["'self'", "data:", "blob:"],
            connectSrc: [
                "'self'",
                "https://api.devnet.solana.com",
                "wss://api.devnet.solana.com",
                "https://api.mainnet-beta.solana.com",
                "wss://api.mainnet-beta.solana.com",
                "https://solshot-server.onrender.com",
                "wss://solshot-server.onrender.com",
                "ws://localhost:5001",
                "wss://localhost:5001",
            ],
            fontSrc: ["'self'", "https://fonts.gstatic.com"],
            frameSrc: ["'none'"],
            objectSrc: ["'none'"],
            baseUri: ["'self'"],
        },
    },
    crossOriginEmbedderPolicy: false,
}))
```

**Note:** The Express server primarily serves the Socket.IO API, not the React SPA (which is served by Vercel or similar). The server CSP protects the API responses and the root `/` endpoint. The meta tag in index.html (from Task 1) is the primary CSP for the SPA. Both should be set for defense in depth.

**Important:** Do NOT add `'unsafe-eval'` — it is not needed. Do NOT add `'unsafe-inline'` to `script-src` — that would defeat the purpose.
