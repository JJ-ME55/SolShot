Add Socket.IO middleware for per-IP connection limiting in `server/index.js`. Place the `io.use()` call AFTER `const io = new socket.Server(...)` (around line 30) and BEFORE `mainsocket(io)` (line 81). Middleware must be registered before the connection handler.

Implementation:

```javascript
// IM-03: Per-IP connection limiting (DB: H024)
const MAX_CONNECTIONS_PER_IP = 100;
const ipConnectionCounts = new Map();

io.use((socket, next) => {
    const ip = (socket.handshake.headers['x-forwarded-for'] || '')
                    .split(',')[0]
                    .trim()
               || socket.handshake.address;

    const current = ipConnectionCounts.get(ip) || 0;
    if (current >= MAX_CONNECTIONS_PER_IP) {
        return next(new Error('connection limit exceeded'));
    }

    ipConnectionCounts.set(ip, current + 1);

    socket.on('disconnect', () => {
        const count = ipConnectionCounts.get(ip) || 1;
        if (count <= 1) {
            ipConnectionCounts.delete(ip);
        } else {
            ipConnectionCounts.set(ip, count - 1);
        }
    });

    next();
});
```

Key details:
- Use `x-forwarded-for` first because Render is a reverse proxy — `socket.handshake.address` would return Render's internal LB IP, making all clients appear as one host
- `split(',')[0].trim()` gets the leftmost (original client) IP from the forwarded chain
- MAX_CONNECTIONS_PER_IP = 100 matches the success criterion ("more than 100 from single IP rejected")
- The disconnect handler decrements the counter; when count reaches 0, the entry is deleted to prevent Map growth
- If middleware rejects (before `next()` succeeds), the socket never fully connects so the disconnect handler won't fire — but the count was never incremented because rejection happens before `ipConnectionCounts.set()`... WAIT, that's wrong. The increment happens BEFORE the reject check. Fix: check BEFORE incrementing.

Correct order:
1. Extract IP
2. Get current count
3. If current >= MAX, reject (return next(new Error(...))) — do NOT increment
4. Otherwise, increment and register disconnect handler
5. Call next()

The code above already has the correct order (check >= MAX before set). Confirmed.
