  <name>Task 2: Increase terrain seed entropy to 128 bits (IM-05)</name>
  <files>server/socket-io/main.js</files>
  <action>
In `server/socket-io/main.js`, find the terrain generation block (around line 2291). Replace the seed generation:

**BEFORE (line 2291):**
```javascript
const seed = crypto.randomInt(1000000)
const { path, heightmap } = generateTerrain(1200, 800, seed)
```

**AFTER:**
```javascript
// IM-05: 128-bit CSPRNG entropy for terrain seed (DB: H038)
const fullSeed = crypto.randomBytes(16).toString('hex');
// Derive 32-bit unsigned int for mulberry32 PRNG (first 4 bytes = 32 bits)
// mulberry32's seededRandom() uses s |= 0 which truncates to 32-bit signed;
// >>> 0 ensures unsigned interpretation
const seed32 = parseInt(fullSeed.slice(0, 8), 16) >>> 0;

const { path, heightmap } = generateTerrain(1200, 800, seed32);
```

Then update the storage and emit to use the full 128-bit hex seed:

**Storage (around line 2298):**
```javascript
// BEFORE:
room.terrainSeed = seed
// AFTER:
room.terrainSeed = fullSeed
```

**Terrain payload cache and emit (around line 2328):**
The `seed` field in the terrainPayload object should use `fullSeed` instead of `seed`:
```javascript
// BEFORE:
seed,
// AFTER:
seed: fullSeed,
```

**Why this is safe for the client:** The client receives the `seed` field in the `terrainGenerated` event but only uses `path`, `heightmap`, `tankPositions`, and `wind` — it does NOT use `seed` for terrain regeneration (verified in client/src/scenes/main/index.js:432). Changing seed from a number (~20 bits) to a hex string (128 bits) does not break any client functionality.

**Why `parseInt(fullSeed.slice(0,8), 16) >>> 0`:**
- `slice(0,8)` takes 8 hex chars = 4 bytes = 32 bits of entropy
- `parseInt(..., 16)` converts hex to number
- `>>> 0` coerces to unsigned 32-bit integer (mulberry32 expects unsigned via `s |= 0`)
- The remaining 96 bits provide entropy diversity — two seeds differing only in upper 96 bits still map to different 32-bit PRNG seeds with overwhelmingly high probability since the first 4 bytes differ

Also ensure there are no other references to the old `seed` variable name in the same scope that would break. The variable was named `seed` — rename all references in the terrain block scope to use `seed32` for the numeric value and `fullSeed` for the hex string.
