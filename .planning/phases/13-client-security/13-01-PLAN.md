**B. Add CSP report-uri directive and POST handler to `server/index.js`** (SEC-02):

1. In the existing `contentSecurityPolicy.directives` object (around line 77-101), add a `reportUri` directive AFTER the `baseUri` line and BEFORE the closing `},`:

```javascript
reportUri: ['/api/csp-report'],
```

2. Add a new POST route AFTER the existing `app.post('/api/admin/reload-keys', ...)` route (around line 133). Add it as follows:

```javascript
// SEC-02: CSP violation reporting endpoint
app.post('/api/csp-report', express.json({ type: 'application/csp-report' }), (req, res) => {
    const report = req.body['csp-report'] || req.body;
    console.error('[CSP Violation]', JSON.stringify({
        directive: report['violated-directive'],
        blocked: report['blocked-uri'],
        document: report['document-uri'],
    }));
    res.status(204).end();
});
```

CRITICAL: The `type: 'application/csp-report'` option in `express.json()` is MANDATORY — browsers send violations with this Content-Type, not `application/json`. Without it, `req.body` will be empty/undefined.

The handler logs violations via `console.error` (which is server-side only and appropriate for operational monitoring). It returns 204 No Content (standard for reporting endpoints). The existing `httpLimiter` (100 req/15min) already covers this route — no additional rate limiting needed.

Do NOT add `console.log` in this handler — that would be ironic given SEC-03. Use `console.error` as shown.
