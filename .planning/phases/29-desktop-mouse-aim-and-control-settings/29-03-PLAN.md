  <action>
**AngleControl.js:**
1. Add `readOnly` to the destructured props
2. When `readOnly` is true:
   - Render the slider with `disabled={true}` and `onChange={() => {}}` (no-op)
   - Remove or disable any editable text input for the angle value — show it as plain text/span instead
   - Keep the visual layout identical (label, value display, slider track) so the HUD doesn't shift
3. When `readOnly` is false (or undefined): existing behavior unchanged — full interactivity

**PowerControl.js:**
1. Same pattern as AngleControl: add `readOnly` prop
2. When `readOnly`: slider disabled with no-op onChange, value display is read-only text
3. When not readOnly: existing behavior unchanged

**BattleHUD.js:**
1. Use the `controlScheme` prop (already passed from Plan 01)
2. Compute: `const mouseAimActive = !isMobile && controlScheme === 'mouse';` (use whatever isMobile detection BattleHUD already has — check for `useIsMobile` import or `window.isMobile` or a prop)
3. Pass `readOnly={mouseAimActive}` to `<AngleControl>` and `<PowerControl>`
4. Conditionally render `<FireButton>`: only show when `!mouseAimActive`
   - Use `{!mouseAimActive && <FireButton ... />}` pattern
   - Do NOT remove the FireButton component — just conditionally render it

**DO NOT:**
- Change the `onChange` prop signature — just don't call it when readOnly
- Remove existing slider styling or layout — readOnly is visual-only change (disabled + no-op)
- Break mobile layout — `mouseAimActive` is false on mobile, so mobile is unaffected
  </action>

5. Mobile viewport: sliders interactive, FIRE button visible (mouseAimActive is false on mobile)
  </verify>
