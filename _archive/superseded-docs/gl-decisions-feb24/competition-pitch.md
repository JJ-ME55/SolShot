# Competition Pitch — Decisions

## Summary
The one-pager's entire gravitational center is "Skill-based SOL wagering — live, not a demo." Jupiter integration serves as track qualification, technical maturity serves as credibility. Everything on the page directs back to the core hook. Solo founder, built with AI, hosted at solshot.gg.

## Decisions

### D1: Core Hook
**Choice:** "Skill-based SOL wagering — live, not a demo." Every element on the one-pager must reinforce this single message.
**Rationale:** Most competition entries are whitepapers or testnet prototypes. SolShot will be live on mainnet at submission — that's the differentiator.
**Alternatives considered:** Leading with Jupiter integration, leading with technical depth, leading with tokenomics
**Affects docs:** [one-pager, competitive-landscape]

### D2: Mainnet Status
**Choice:** "Live on Solana mainnet" — no hedging, no footnotes. Will be fully deployed and resolved before competition submission.
**Rationale:** Game, escrow, and token will all be mainnet-live by submission date. No need to qualify.
**Alternatives considered:** "Live on devnet," "Playable now" with footnote, hedged language
**Affects docs:** [one-pager, how-to-play, crypto-explainer]

### D3: Stats Hierarchy
**Choice:** Feature stats in this priority order:
1. 90/7/3 trustless escrow split — concrete, shows real economic design
2. 3 completed security audits — shows maturity and seriousness
3. 10M SHOT fixed supply, mint authority burned — one line that tells everything about tokenomics
4. 20 weapons / 4 match modes / BO1-BO3-BO5 — depth of gameplay, proves it's a real game not a tech demo
**Rationale:** Lead with trustless economics (the differentiator), back with credibility (audits), then token design, then gameplay depth. Lines of code and matches played dropped unless numbers are impressive.
**Alternatives considered:** Leading with gameplay stats, including LOC/match counts
**Affects docs:** [one-pager, competitive-landscape]

### D4: Jupiter Integration Framing
**Choice:** JUP integration is positioned as track qualification, not the headline. In-game SOL<>SHOT swap, live JUP price feed, JUP-supported wallet connector.
**Rationale:** Jupiter features are real and planned, but they're not the core value prop. They explain why SolShot belongs in the JUP track without overshadowing the wagering hook.
**Alternatives considered:** Leading with Jupiter as primary differentiator
**Affects docs:** [one-pager]

### D5: Team Section
**Choice:** Solo founder, built with AI. No ecosystem partner claims. Keep it tight and honest.
**Rationale:** Solo founder shipping a full-stack wagering game with 3 security audits is impressive scope-per-person. Claiming ecosystem partners without real relationships would be cheesy and verifiable.
**Alternatives considered:** Listing Meteora/Jupiter as ecosystem team, factual integrations list
**Affects docs:** [one-pager]

### D6: Demo / Link
**Choice:** solshot.gg — the live game URL. Judges can click and play.
**Rationale:** A live, playable URL is the ultimate proof point for "not a demo."
**Alternatives considered:** Repo link, separate demo environment
**Affects docs:** [one-pager, how-to-play]

None.

## Raw Notes
- The phrase "live, not a demo" should be used verbatim or near-verbatim on the one-pager
- The 90/7/3 split stat is valued specifically because it's "concrete" and "trustless" — use those exact framings
- "Shows real game not a tech demo" is the rationale for including gameplay stats — they're proof of depth, not the headline
